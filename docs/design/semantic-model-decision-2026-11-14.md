# 语义模型决策：节点 / 关系 / 探索方向

日期：2026-11-14
状态：产品负责人确认语义分工，本文记录决策与后续算法调整依据。
范围：只涉及语义模型与生成规则，不改界面视觉。

## 1. 一句话决策

- **节点 = 一个具体的名词概念**（"是什么"）；
- **节点 MD = 这个概念下用户的学习、了解、思考记录**（"我围绕它学到了什么"）；
- **关系线 = 两个概念之间的归类与定位**（"它和谁同类 / 由什么组成 / 在什么之前 / 与什么对比"），不是任意连接；
- **探索方向 = 从边缘节点向外延伸的下一步学习路径**；每个节点都有方向数据，但**只有边缘节点把方向画成线**；
- **建筑（副本）= 由概念与关系结构触发的练习单元**（流程 / 领域），不是用户新建的装饰。

## 2. 三类对象重新定义

### 2.1 节点（概念）

| 项 | 定义 |
| --- | --- |
| 本体 | **名词性概念**：概念 / 方法 / 组件 / 指标 / 工具（类型白名单只允许这五类；步骤不是类型，是过程里的角色，见下） |
| 承担职责 | 回答"这是什么"；作为关系两端、方向起点、题目主体 |
| 节点 MD | 由用户围绕该概念产生的学习记录：来源、理解、疑问、资料、关系定位、继续探索；**自由区归用户，AI 不覆盖** |
| 不允许 | 把动词、代词、泛化词、整句、疑问句当节点；把"一个关键词"当概念；把"问题""领域"当节点类型 |

**为什么节点类型里没有"问题"（重要修正）**

- "问题"是**疑问/知识缺口**，属于探索方向（Direction），不是名词概念；
- 用户的提问 → 进方向列表或 AI 对话，不生成以问句为名的节点；
- 如果问句里提到了一个具体名词（"幻觉问题怎么解决？"），只抽取"幻觉"这类名词概念，问题本身变成该概念的方向；
- 同理，`领域` 不是节点类型，它是领域副本（建筑）的聚类标签；
- `步骤` 也不是节点类型，也**不是节点字段**：步骤是**流程副本候选里的上下文角色**（同一个概念在 A 流程里是步骤、在 B 流程里可能是组件），只在副本候选中记录 ordered steps，不写回节点属性。

### 2.2 关系（归类与定位）

关系不是"一条线"，而是**一个可解释的语义断言**：

| 维度 | 内容 |
| --- | --- |
| 谓词（知识类型） | 归类 `kindOf`、组成 `partOf`、前置 `prerequisite`、对比 `contrast`、替代 `alternative`、相关 `related` |
| 方向 | 按谓词固定语义方向（见 3.2），不是随便 A→B |
| 理由 | 为什么这两个概念是这样定位的（证据句 + 解释） |
| 关系 MD | 归类/定位说明 + 依据 + 用户补充 |
| 状态 | 正式 / 建议（虚线）/ 争议（暂停出题依据）/ 已修订 |

**探索来源线**（新节点从哪个旧节点延伸）是"探索路径"，不是知识谓词；它单独存在、单独标识，不能和"归类与定位"混为一种关系。

### 2.3 探索方向（边缘节点的延伸）

| 项 | 决策 |
| --- | --- |
| 数据 | 每个节点都可以有 0–3 条方向（问题 + 理由 + 目标提示） |
| 展示 | **只有边缘节点渲染方向线**（地图上表现为短箭头/路牌）；非边缘节点的方向在节点 MD 的"继续探索"区列出，不画线 |
| 边缘节点 | 在正式关系图中**没有向外延伸的知识关系**（出度为 0），或最近新增且尚未展开的节点；由后端标记 `frontier` |
| 消费 | 点击方向 → AI 对话 → 产生新节点/关系 → 该方向 `consumed`，重新计算边缘 |
| 为什么限制边缘 | 避免每个节点都射出方向线导致地图爆炸；方向的意义是"往外走"，内部节点已经有下一步了 |

### 2.4 建筑（副本）

- **流程副本**：AI 识别"同一过程"候选，硬校验 3–6 步、每对相邻有过程证据、顺序唯一、每步有来源；
- **领域副本**：AI 识别"同一领域"候选，硬校验 ≥4 个概念、有共同上位概念或共同来源；
- 出现条件（detected）与可挑战条件（playable）分开；不是用户新建；
- 步骤只是候选里的上下文角色，不写回节点（不给节点加 `role`）；
- 完整规则见 [dungeon-generation-rules.md](dungeon-generation-rules.md)。

## 3. 关系类型与方向约定

### 3.1 谓词表

| 谓词 | 中文 | 语义方向 | 例子 |
| --- | --- | --- | --- |
| `kindOf` | 归类 | 具体 → 上位 | Rerank → 精排方法 |
| `partOf` | 组成 | 部分 → 整体（或整体 → 部分需统一，见下） | BM25 → 混合检索 |
| `prerequisite` | 前置 | 前置概念 → 依赖概念 | 召回 → Rerank |
| `contrast` | 对比 | 无方向，展示为双向/对比 | BM25 ↔ 向量召回 |
| `alternative` | 替代 | 被替代 → 替代者 | 全文检索 → 向量检索 |
| `related` | 相关 | 无方向 | RAG ↔ 评测 |

**方向统一规则**（必须固定，否则同一关系画反）：

- `kindOf`：具体 → 上位（子概念指向父概念）；
- `partOf`：部分 → 整体（组件指向整体）；
- `prerequisite`：前置 → 后续；
- `contrast` / `related`：无方向（渲染时用无箭头或双向）；
- `alternative`：旧方案 → 新方案。

### 3.2 地图线型映射

| 知识状态 | 地图表现 |
| --- | --- |
| 有证据、置信度高 | 正式关系（实线，不可删除） |
| 有候选但证据不足 | 建议关系（虚线，需用户接受） |
| 探索来路 | 来源线（单独标识，不参与归类判断） |
| 未探索 | 方向线（仅边缘节点渲染） |

## 4. 数据模型调整（设计）

```text
Node:
  id, world_id, name,
  type(概念/方法/组件/指标/工具),        -- 只允许名词概念类型
  definition(AI 初稿), aliases[], source_span_id,
  learning_md(用户自由区), frontier(bool), tier, hidden, x, y

Relation:
  id, world_id, src, dst,
  predicate(kindOf/partOf/prerequisite/contrast/alternative/related),
  label, rationale, evidence_span_id,
  origin(auto/manual/accept_suggestion),
  confidence, claim_status(normal/disputed/revised), revision,
  md(关系说明), created_at

Direction:
  id, world_id, node_id,
  question, reason, target_hint,
  status(open/consumed/archived), consumed_span_id, created_at

SourceSpan:
  id, world_id, session_id, text, revision, created_at
```

要点：

- **Direction 独立成表**，不再复用 edges（现在自环/方向反了就是复用 edges 导致的）；
- Relation 增加 `predicate/evidence/rationale/claim_status/revision`，关系不再是自由文本；
- Node 的 `frontier` 由后端计算（出度为 0 或新节点未展开），方向线只渲染 frontier；
- SourceSpan 给节点/关系/方向提供证据来源。

## 5. 渲染与交互调整

1. **关系线**：线上显示谓词（或悬停显示）；点击打开关系 MD（归类/定位说明 + 依据）；
2. **节点 MD** 分四区：
   - 来源（哪段话产生）
   - 我的理解（用户自由区）
   - 关系定位（关联概念 + 谓词 + 一句理由）
   - 继续探索（该节点的方向列表，点击进入 AI 对话）
3. **方向线**：只从 frontier 节点画出，最多 2–3 条；非 frontier 节点的方向在 MD 里列出；
4. **探索来源线**：与知识关系视觉区分（例如更淡、标注"来路"），不显示谓词；
5. **副本**：流程=步骤链、领域=归类簇；出现与可挑战状态分开显示。

## 6. 验收标准的改变

从"有没有节点"改成"节点和关系有没有意义"：

| 指标 | 目标 |
| --- | --- |
| 节点可解释率 | 有类型 + 有定义 + 有证据来源 ≥ 95% |
| 关系可解释率 | 有谓词 + 有证据 + 有理由 ≥ 90% |
| 谓词准确率 | 人工抽样 ≥ 0.7 |
| 方向相关性 | 方向问题与该概念缺口相关（人工抽样 ≥ 0.7） |
| 边缘方向覆盖率 | 每个 frontier 节点至少 1 条方向 ≥ 90% |
| 非边缘方向不画线 | 100%（渲染规则） |

## 7. 与现有实现的差异（需要改的点）

1. 节点没有 type/definition/evidence/aliases → 补；
2. 关系只有 4 类地图线、label 自由文本 → 补谓词/理由/证据/方向约定；
3. 方向复用 edges（自环/反向）→ 独立 Direction 表；
4. 每个节点随机出方向 → 只给 frontier 出线，内部在 MD；
5. 节点 MD 没有"关系定位/继续探索"区 → 补；
6. 探索来源线与知识关系未区分 → 视觉与数据分开；
7. 副本检测是纯 DFS 规则 → 改为"AI 候选 + 硬校验"，并用谓词/证据判断流程与领域。
