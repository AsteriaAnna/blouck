# 生成算法 v2：概念节点 / 归类定位关系 / 边缘探索方向

日期：2026-11-14
依据：`docs/design/semantic-model-decision-2026-11-14.md`、两份基线文档、`server/eval` 基线结果
状态：设计稿（待产品确认后实现）

## 1. 目标

把「一段学习语音」变成一张**有语义、可解释、可探索**的概念地图：

- 节点是**名词概念**，不是关键词；
- 关系是**归类与定位**（谓词 + 方向 + 证据 + 理由），不是任意连线；
- 方向是**边缘节点向外延伸的学习路径**，不是关系的一种；
- 副本是**由概念结构触发**的练习（流程 = 步骤链，领域 = 归类簇）。

非目标：不追求"抽到越多越好"；不做开放式知识库；不做关系题（按 MVP 文档延后）。

## 2. 流水线

```text
ASR 稳定片段（SourceSpan）
  → 概念候选（名词短语 + 类型 + 定义 + 证据）
  → 概念规范化（别名/去重/合并）
  → 节点落图（位置 + MD 初稿）
  → 关系候选（共现/邻居/向量 top-k）
  → 关系分类与定位（谓词 + 方向 + 理由 + 证据）
  → 方向生成（每个节点 0–3 条；仅边缘节点渲染）
  → 副本候选（流程链 / 归类簇）+ 硬校验
  → 评测（eval）与人工抽样
```

## 3. 概念（节点）生成

### 3.1 候选生成（LLM + 结构约束）

输入：SourceSpan 文本 + 当前焦点概念 + 已有概念列表。

输出 JSON（每条）：

```json
{
  "name": "Rerank",
  "type": "方法",
  "definition": "召回之后对候选集重新打分的精排阶段",
  "aliases": ["重排"],
  "evidence": "然后用 Rerank 精排",
  "confidence": 0.92
}
```

**类型白名单**：`概念 / 方法 / 组件 / 指标 / 工具`（只有名词概念类型）。

**步骤不是节点属性**：不要给节点加 `role=步骤`。一个概念是不是"步骤"取决于上下文——它在某个流程候选里可以是步骤，在另一个流程里可能是组件。流程检测只在候选里记录 ordered steps，不写回节点。

**明确禁止**：
- `问题` 不是节点类型——疑问句/知识缺口进入 Direction，不生成以问句为名的节点；
- `领域` 不是节点类型——它是领域副本（建筑）的聚类标签；
- 如果用户说"幻觉问题怎么解决"，只抽"幻觉"这个名词概念，问题本身变成"幻觉"的方向；
- 名词性测试：节点名必须能回答"什么是 X？"，且 X 不是疑问句/命令句。

### 3.2 校验（不过就不落图）

| 规则 | 说明 |
| --- | --- |
| evidence 必须是原文子串 | 防止模型编造来源 |
| name 长度 2–20，非停用词/代词/动词 | 示例："然后""这个""可以做" 拒绝 |
| **name 必须是名词性短语** | 疑问句、命令句、"怎么/为什么/如何"开头 → 拒绝（转 Direction） |
| **type 只能是 概念/方法/组件/指标/工具** | 出现"问题/领域/步骤"等非法类型 → 拒绝或归一 |
| definition 非空且不为同义重复 | 否则标记"待补充" |
| confidence ≥ 0.6 | 低于阈值进"待确认"，不落图 |
| 单片段最多 5 个新节点 | 防止刷屏 |

### 3.3 规范化与去重

1. 精确匹配：名称/别名（忽略大小写、空格、标点）→ 复用节点；
2. 向量相似度 ≥ 0.92 → LLM 裁决：
   - `same` → 合并（别名合并，definition 取更长者，证据追加）；
   - `parent_child` → 建立 `kindOf` 关系，不合并；
   - `different` → 各自建节点；
3. 含义不明确时**不合并**（宁可多，不可错并）。

### 3.4 节点 MD 初稿

```markdown
## Rerank

> 来源：混合检索之后，用 Rerank 精排。

### AI 初稿（可删）
召回之后对候选集重新打分的精排阶段。

### 我的理解
（用户自由编辑，AI 不覆盖）
```

### 3.5 参数

| 参数 | 起始值 |
| --- | --- |
| 单片段最多新节点 | 5 |
| 实体 confidence 阈值 | 0.6 |
| 名称长度 | 2–20 |
| 向量去重阈值 | 0.92 |
| evidence 必须为原文子串 | 是 |

## 4. 关系（归类与定位）生成

### 4.1 谓词与方向（固定）

| 谓词 | 语义 | 方向 | 判定线索 |
| --- | --- | --- | --- |
| `kindOf` | 归类 | 具体 → 上位 | "是一种/属于/某类" |
| `partOf` | 组成 | 部分 → 整体 | "组成/包含/一部分/模块" |
| `prerequisite` | 前置 | 前置 → 后续 | "先/再/需要/基础/之后" |
| `contrast` | 对比 | 无方向 | "相比/区别/而…更" |
| `alternative` | 替代 | 旧 → 新 | "替代/换成/不如用" |
| `related` | 相关 | 无方向 | 明确共现 + 语义关联句 |

方向必须按上表归一化，避免同一关系画反。

### 4.2 候选生成

1. **邻域候选**：新节点与焦点、焦点邻居；
2. **相似候选**：向量 top-5 的已有概念；
3. **显式候选**：文本中同时出现的概念对。

候选对交给 LLM 分类：`predicate + 方向 + 理由 + evidence + confidence`，要求 evidence 同时包含两端概念名（或明确指代）。

### 4.3 落地规则

| 条件 | 结果 |
| --- | --- |
| confidence ≥ 0.75 且 evidence 完整 | 正式关系（实线） |
| 0.5 ≤ confidence < 0.75 | 建议关系（虚线，带候选关系名） |
| < 0.5 | 不建关系（只保留来源线） |
| 用户接受建议 | 转正式 + 生成关系名/理由/MD |
| 用户手动连线 | LLM 给 1–3 个候选谓词/理由，用户确认后建正式（origin=manual） |

**关系 MD 结构**：

```markdown
## 归类/定位：Rerank —kindOf→ 精排方法

- 依据：文本中"精排阶段"的直接断言
- 解释：Rerank 是精排的一种实现
- 来源：SourceSpan #...
```

### 4.4 去重与冲突

- 同一对概念 + 同一谓词 → 合并证据，不重复建边；
- 同一对概念最多 2 种谓词（不同语义）；
- `contrast` 与 `related` 共存时，优先显示对比；
- 方向冲突（A→B 与 B→A）按谓词方向约定归一化。

### 4.5 参数

| 参数 | 起始值 |
| --- | --- |
| 正式关系 confidence | ≥0.75 |
| 建议关系 confidence | 0.5–0.75 |
| 每新节点最多语义关系 | 3 |
| 相似候选 top-k | 5 |
| 同对最多谓词数 | 2 |
| evidence 需含两端 | 是 |

## 5. 探索方向（边缘节点）

### 5.1 每个节点都有方向数据

方向来源（按优先级）：

1. 节点 definition 中的未解释点（"为什么/如何/区别"）；
2. 缺失的归类/前置/对比（例如"它和 X 有什么区别？"）；
3. 邻居缺口（邻居有 Y，但它没有）；
4. 用户 MD 中的疑问句。

输出：

```json
{
  "question": "Rerank 和向量相似度排序的区别是什么？",
  "reason": "节点缺少与向量相似度的对比",
  "target_hint": "向量相似度",
  "confidence": 0.8
}
```

### 5.2 校验

- 问题必须提到本节点名或节点核心概念；
- 长度 8–60 字；
- 不能是泛化模板（"还能学什么"）；
- 每节点最多 3 条，去重（同义问题合并）。

### 5.3 边缘节点判定（frontier）

```text
frontier = 隐藏=false
        AND (知识关系出度为 0
             OR (最近新增 AND 未被展开))
```

- 出度只算知识谓词（kindOf/partOf/prerequisite/contrast/alternative/related），不算探索来源线与方向线；
- 每次新增节点/关系后重算；
- 被用户点击"继续探索"后，方向 `consumed`，节点可能不再是前沿。

### 5.4 渲染规则

| 节点状态 | 方向展示 |
| --- | --- |
| frontier | 地图上画方向（最多 2 条，短箭头/路牌） |
| 非 frontier | 不画线；节点 MD"继续探索"区列出方向 |
| consumed | 不显示 |

### 5.5 参数

| 参数 | 起始值 |
| --- | --- |
| 每节点方向数 | 0–3 |
| frontier 渲染上限 | 2 |
| 问题长度 | 8–60 字 |
| 方向 confidence 阈值 | 0.6 |

## 6. 副本生成

副本的完整规则见独立文档：[dungeon-generation-rules.md](dungeon-generation-rules.md)。

要点：

- **流程副本**：AI 在新增节点邻域提出"同一过程"候选（processName + ordered steps + 每对相邻步骤的证据句）→ 程序硬校验：3–6 步、每对相邻有过程证据、**唯一拓扑序**、无环、每步有 SourceSpan、粒度一致、无隐藏/争议成员、confidence≥0.75；任一不过就不生成。
- **领域副本**：AI 提出"同一领域"候选（domainName + members + 共同依据）→ 硬校验：成员 4–8、必须有共同上位概念（kindOf）或共同 SourceSpan、命名不与成员/已有领域重复、成员都有 definition+evidence、无争议/隐藏、与已有领域重叠≤50%、confidence≥0.7。
- **状态**：`detected`（出现但锁定）→ `playable`（流程：链上每步 tier≥1；领域：≥2 个相关节点 tier≥1）→ `cleared`；依据变化 → `stale`（保留历史、暂停出题）。
- **语义边界**：只用正式关系与 SourceSpan，不把 suggest/direction/来源线当依据；成员/步骤必须是已存在的概念节点；不给节点加 `role=步骤`（步骤是上下文角色）。
- **检测**：每次抽取后只扫新增节点 1–2 跳；指纹去重；每世界每类上限 3；同邻域 10 分钟冷却。
- **领域题目**：按用户+世界+领域+Asia/Shanghai 日期，每日 10 道混合题（填空/判断/解答），逐题占额，重答不占新额，跨天新题，不计节点三档。

## 8. 评测方案（v2）

### 8.1 指标

| 指标 | 目标 |
| --- | --- |
| 节点可解释率（type+definition+evidence） | ≥95% |
| 实体 P/R | P≥0.9 / R≥0.8 |
| 关系谓词准确率 | ≥0.75 |
| 关系 P/R | P≥0.8 / R≥0.7 |
| 关系方向合法率 | 100%（按谓词方向表） |
| 证据覆盖率 | 100% |
| 方向相关性（人工抽样） | ≥0.7 |
| frontier 方向覆盖 | ≥90% |
| 副本检测 precision/recall | ≥0.8 / ≥0.7 |

### 8.2 用例扩展

在现有 `server/eval/cases.json` 基础上，为每条关系增加：

```json
{ "from": "Rerank", "to": "精排", "predicate": "kindOf", "direction": "Rerank→精排", "evidence": "..." }
```

新增用例类型：

- 否定句（"RAG 不是微调"）→ 不得生成 `partOf`；
- 对比句 → 必须 `contrast`；
- 多解流程 → 不得生成流程副本；
- 非 frontier 节点 → 方向不得画线（渲染规则检查）；
- 同义概念（"重排/精排"）→ 别名合并；
- 模糊指代（"这个东西"）→ 不得建节点。

## 9. 实施顺序

1. 数据模型迁移（Node 字段、Relation 谓词/证据、Direction 表、SourceSpan、frontier）；
2. 概念抽取 v2（schema + 校验 + 去重）；
3. 关系 v2（谓词/方向/证据/建议/手动/接受命名）；
4. 方向独立化 + frontier 渲染；
5. 副本 v2（AI 候选 + 硬校验 + 领域混合题型）；
6. eval v2 + 基线对比；
7. 最后才补 3D 的 LOD/搜索等表现层。

## 10. 风险

- 中文谓词分类不稳定 → 规则+证据+人工抽样兜底；
- 关系召回低 → 两阶段候选 + 多轮 gleaning；
- 方向生成泛化 → 强校验（必须提到本节点概念）；
- 副本唯一序检测成本 → 3–6 步枚举可接受；
- 成本/延迟 → 每片段 1–2 次模型调用，控制在预算内；
- 旧数据迁移 → 现有 edges 可映射为 `related`，逐步补谓词。

## 12. 实施进度（2026-11-14）

已实现：

- 节点 v2：`type/definition/aliases/source_span_id/frontier`；
- 关系 v2：`source/target/predicate/evidence/confidence/origin/claim_status/revision`；
- 抽取：证据必须是原文子串、名称名词性校验、类型白名单、confidence 阈值、别名去重、每个新节点强制来源边；
- 方向：独立 `directions` 表；只给 frontier 节点物化方向线（每节点最多 2 条）；非 frontier 在节点 MD 展示；
- 副本：流程唯一序校验、领域共同依据校验、位置留白、状态 `detected/playable/cleared`、领域每日 10 道混合题；
- 3D：相机自适应框住节点+副本；
- **手动连线**：节点抽屉"手动关联"（选概念 + 谓词 + 关系名，留空由 LLM 命名）；
- **接受建议**：虚线 → 正式时由 LLM 生成关系名/谓词/说明；
- **LLM 方向**：每批节点调用 `suggestDirections`，失败才用模板；
- **LLM 副本候选**：`detectDungeons` 提流程/领域候选，程序用唯一序/共同依据校验；
- **stale**：成员隐藏或关系争议时自动 `stale`，恢复后回到 `detected/playable`。

评测（`pnpm eval`）：实体 P/R = 100%/70%，关系 P/R = 32.4%/46.0%，谓词准确率 87.0%，线型一致率 91.3%，证据覆盖率 46.0%。

待办：

- 证据覆盖率提升（当前 46%：匹配上的关系里不到一半带证据）；
- 方向质量单独评测（方向已独立成表，旧评测只统计关系输出）；
- `version/fingerprint` 变更策略（当前只落库未使用）；
- 领域题组接 LLM 出题（当前确定性题面 + 定义答案）。
