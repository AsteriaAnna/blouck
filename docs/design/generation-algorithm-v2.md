# 生成算法 v2：概念节点 / 归类定位关系 / 边缘探索方向

日期：2026-11-14
依据：`docs/design/semantic-model-decision-2026-11-14.md`、两份基线文档、`server/eval` 基线结果
状态：设计稿（待产品确认后实现）

## 1. 目标

把「一段学习语音」变成一张**有语义、可解释、可探索**的概念地图：

- 节点是**名词概念**，不是关键词；
- 关系是**归类与定位**（谓词 + 方向 + 证据 + 理由），不是任意连线；
- 方向是**边缘节点向外延伸的学习路径**，不是关系的一种；
- 副本是**由概念结构触发**的练习（流程 = 步骤链，领域 = 归类簇）。

非目标：不追求"抽到越多越好"；不做开放式知识库；不做关系题（按 MVP 文档延后）。

## 2. 流水线

```text
ASR 稳定片段（SourceSpan）
  → 概念候选（名词短语 + 类型 + 定义 + 证据）
  → 概念规范化（别名/去重/合并）
  → 节点落图（位置 + MD 初稿）
  → 关系候选（共现/邻居/向量 top-k）
  → 关系分类与定位（谓词 + 方向 + 理由 + 证据）
  → 方向生成（每个节点 0–3 条；仅边缘节点渲染）
  → 副本候选（流程链 / 归类簇）+ 硬校验
  → 评测（eval）与人工抽样
```

## 3. 概念（节点）生成

### 3.1 候选生成（LLM + 结构约束）

输入：SourceSpan 文本 + 当前焦点概念 + 已有概念列表。

输出 JSON（每条）：

```json
{
  "name": "Rerank",
  "type": "方法",
  "definition": "召回之后对候选集重新打分的精排阶段",
  "aliases": ["重排"],
  "evidence": "然后用 Rerank 精排",
  "confidence": 0.92
}
```

**类型白名单**：`概念 / 方法 / 组件 / 指标 / 步骤 / 问题 / 工具 / 领域`。

### 3.2 校验（不过就不落图）

| 规则 | 说明 |
| --- | --- |
| evidence 必须是原文子串 | 防止模型编造来源 |
| name 长度 2–20，非停用词/代词/动词 | 示例："然后""这个""可以做" 拒绝 |
| type 在白名单 | 未知类型归"概念"或拒绝 |
| definition 非空且不为同义重复 | 否则标记"待补充" |
| confidence ≥ 0.6 | 低于阈值进"待确认"，不落图 |
| 单片段最多 5 个新节点 | 防止刷屏 |

### 3.3 规范化与去重

1. 精确匹配：名称/别名（忽略大小写、空格、标点）→ 复用节点；
2. 向量相似度 ≥ 0.92 → LLM 裁决：
   - `same` → 合并（别名合并，definition 取更长者，证据追加）；
   - `parent_child` → 建立 `kindOf` 关系，不合并；
   - `different` → 各自建节点；
3. 含义不明确时**不合并**（宁可多，不可错并）。

### 3.4 节点 MD 初稿

```markdown
## Rerank

> 来源：混合检索之后，用 Rerank 精排。

### AI 初稿（可删）
召回之后对候选集重新打分的精排阶段。

### 我的理解
（用户自由编辑，AI 不覆盖）
```

### 3.5 参数

| 参数 | 起始值 |
| --- | --- |
| 单片段最多新节点 | 5 |
| 实体 confidence 阈值 | 0.6 |
| 名称长度 | 2–20 |
| 向量去重阈值 | 0.92 |
| evidence 必须为原文子串 | 是 |

## 4. 关系（归类与定位）生成

### 4.1 谓词与方向（固定）

| 谓词 | 语义 | 方向 | 判定线索 |
| --- | --- | --- | --- |
| `kindOf` | 归类 | 具体 → 上位 | "是一种/属于/某类" |
| `partOf` | 组成 | 部分 → 整体 | "组成/包含/一部分/模块" |
| `prerequisite` | 前置 | 前置 → 后续 | "先/再/需要/基础/之后" |
| `contrast` | 对比 | 无方向 | "相比/区别/而…更" |
| `alternative` | 替代 | 旧 → 新 | "替代/换成/不如用" |
| `related` | 相关 | 无方向 | 明确共现 + 语义关联句 |

方向必须按上表归一化，避免同一关系画反。

### 4.2 候选生成

1. **邻域候选**：新节点与焦点、焦点邻居；
2. **相似候选**：向量 top-5 的已有概念；
3. **显式候选**：文本中同时出现的概念对。

候选对交给 LLM 分类：`predicate + 方向 + 理由 + evidence + confidence`，要求 evidence 同时包含两端概念名（或明确指代）。

### 4.3 落地规则

| 条件 | 结果 |
| --- | --- |
| confidence ≥ 0.75 且 evidence 完整 | 正式关系（实线） |
| 0.5 ≤ confidence < 0.75 | 建议关系（虚线，带候选关系名） |
| < 0.5 | 不建关系（只保留来源线） |
| 用户接受建议 | 转正式 + 生成关系名/理由/MD |
| 用户手动连线 | LLM 给 1–3 个候选谓词/理由，用户确认后建正式（origin=manual） |

**关系 MD 结构**：

```markdown
## 归类/定位：Rerank —kindOf→ 精排方法

- 依据：文本中"精排阶段"的直接断言
- 解释：Rerank 是精排的一种实现
- 来源：SourceSpan #...
```

### 4.4 去重与冲突

- 同一对概念 + 同一谓词 → 合并证据，不重复建边；
- 同一对概念最多 2 种谓词（不同语义）；
- `contrast` 与 `related` 共存时，优先显示对比；
- 方向冲突（A→B 与 B→A）按谓词方向约定归一化。

### 4.5 参数

| 参数 | 起始值 |
| --- | --- |
| 正式关系 confidence | ≥0.75 |
| 建议关系 confidence | 0.5–0.75 |
| 每新节点最多语义关系 | 3 |
| 相似候选 top-k | 5 |
| 同对最多谓词数 | 2 |
| evidence 需含两端 | 是 |

## 5. 探索方向（边缘节点）

### 5.1 每个节点都有方向数据

方向来源（按优先级）：

1. 节点 definition 中的未解释点（"为什么/如何/区别"）；
2. 缺失的归类/前置/对比（例如"它和 X 有什么区别？"）；
3. 邻居缺口（邻居有 Y，但它没有）；
4. 用户 MD 中的疑问句。

输出：

```json
{
  "question": "Rerank 和向量相似度排序的区别是什么？",
  "reason": "节点缺少与向量相似度的对比",
  "target_hint": "向量相似度",
  "confidence": 0.8
}
```

### 5.2 校验

- 问题必须提到本节点名或节点核心概念；
- 长度 8–60 字；
- 不能是泛化模板（"还能学什么"）；
- 每节点最多 3 条，去重（同义问题合并）。

### 5.3 边缘节点判定（frontier）

```text
frontier = 隐藏=false
        AND (知识关系出度为 0
             OR (最近新增 AND 未被展开))
```

- 出度只算知识谓词（kindOf/partOf/prerequisite/contrast/alternative/related），不算探索来源线与方向线；
- 每次新增节点/关系后重算；
- 被用户点击"继续探索"后，方向 `consumed`，节点可能不再是前沿。

### 5.4 渲染规则

| 节点状态 | 方向展示 |
| --- | --- |
| frontier | 地图上画方向（最多 2 条，短箭头/路牌） |
| 非 frontier | 不画线；节点 MD"继续探索"区列出方向 |
| consumed | 不显示 |

### 5.5 参数

| 参数 | 起始值 |
| --- | --- |
| 每节点方向数 | 0–3 |
| frontier 渲染上限 | 2 |
| 问题长度 | 8–60 字 |
| 方向 confidence 阈值 | 0.6 |

## 6. 副本生成

### 6.1 流程副本

**候选**：步骤型节点组成的链（`prerequisite` / `partOf`），由 AI 在新增节点邻域判断"是否为同一过程"。

**硬校验（全过才生成）**：

1. 3–6 步；
2. 相邻步骤有过程证据（先/再/然后/最后/之后）；
3. 每步有 SourceSpan；
4. 无环；
5. **唯一拓扑序**（枚举所有合法顺序，>1 种 → 不生成）；
6. 粒度一致（都是步骤型节点）。

锚点 = 链首；`detected`（显示但锁定）→ 链上每节点 tier≥1 才 `playable`。

### 6.2 领域副本

**候选**：同一 `kindOf` 上位概念下的概念簇，或共享来源的概念组。

**硬校验**：

1. ≥4 个概念；
2. 成员间 ≥2 条正式关系，或共享同一 SourceSpan；
3. 领域名不与已有建筑重复；
4. 每个成员有 definition/evidence。

锚点 = 成员中度数最高者；`detected` → 相关节点 ≥2 个 tier≥1 才 `playable`。

### 6.3 领域题目

- 每日 10 题（按用户 + 领域 + Asia/Shanghai 日期），逐题扣减；
- 题型混合：填空（标准答案 + 可接受别名，本地判定）、判断（本地判定）、解答（AI 判定）；
- 重答原题不占新额度；跨天生成新题；
- 领域题不计入节点三档。

### 6.4 参数

| 参数 | 起始值 |
| --- | --- |
| 流程步数 | 3–6 |
| 唯一拓扑序 | 必须 |
| 每步来源 | 必须 |
| 领域最少概念 | 4 |
| 领域每日题数 | 10 |
| 每世界每类副本上限 | 3 |

## 7. 技术参考

这些做法有成熟研究/工程依据，我们不需要引入新框架：

| 主题 | 参考 | 用途 |
| --- | --- | --- |
| 关系词表 | [ConceptNet](https://conceptnet.io/)（`/r/IsA`、`/r/PartOf`、`/r/UsedFor`、`/r/RelatedTo` 等，多语言） | 谓词与方向约定的词表基础 |
| 分类体系构建 | [LLMs for Creation/Enrichment/Evaluation of Taxonomic Graphs](https://journals.sagepub.com/doi/10.1177/22104968251404186)、[taxonomy induction 论文](https://ceur-ws.org/Vol-2211/paper-10.pdf) | `kindOf`/`partOf` 的抽取与合并 |
| 知识缺口提问 | [Learning to Ask: Autonomous Knowledge Acquisition](https://zenodo.org/records/20114629/files/paper.pdf)、[Counterfactual Question Generation](https://ojs.aaai.org/index.php/AAAI/article/view/39023) | 方向问题的生成与校验 |
| 学习路径 | [Adaptive knowledge graph and learning path generation](https://link.springer.com/article/10.1007/s44163-026-01379-w) | 前置关系与副本顺序 |
| 增量图谱/来源 | GraphRAG/LightRAG/Graphiti 的 episode→fact 思路 | SourceSpan、幂等、旧结果拒绝（只借思路） |

**结论**：现有技术栈（豆包 ASR + DeepSeek + Node/SQLite + 3D）足够实现；关键是按上面的 schema 与校验重写抽取，而不是换框架。

## 8. 评测方案（v2）

### 8.1 指标

| 指标 | 目标 |
| --- | --- |
| 节点可解释率（type+definition+evidence） | ≥95% |
| 实体 P/R | P≥0.9 / R≥0.8 |
| 关系谓词准确率 | ≥0.75 |
| 关系 P/R | P≥0.8 / R≥0.7 |
| 关系方向合法率 | 100%（按谓词方向表） |
| 证据覆盖率 | 100% |
| 方向相关性（人工抽样） | ≥0.7 |
| frontier 方向覆盖 | ≥90% |
| 副本检测 precision/recall | ≥0.8 / ≥0.7 |

### 8.2 用例扩展

在现有 `server/eval/cases.json` 基础上，为每条关系增加：

```json
{ "from": "Rerank", "to": "精排", "predicate": "kindOf", "direction": "Rerank→精排", "evidence": "..." }
```

新增用例类型：

- 否定句（"RAG 不是微调"）→ 不得生成 `partOf`；
- 对比句 → 必须 `contrast`；
- 多解流程 → 不得生成流程副本；
- 非 frontier 节点 → 方向不得画线（渲染规则检查）；
- 同义概念（"重排/精排"）→ 别名合并；
- 模糊指代（"这个东西"）→ 不得建节点。

## 9. 实施顺序

1. 数据模型迁移（Node 字段、Relation 谓词/证据、Direction 表、SourceSpan、frontier）；
2. 概念抽取 v2（schema + 校验 + 去重）；
3. 关系 v2（谓词/方向/证据/建议/手动/接受命名）；
4. 方向独立化 + frontier 渲染；
5. 副本 v2（AI 候选 + 硬校验 + 领域混合题型）；
6. eval v2 + 基线对比；
7. 最后才补 3D 的 LOD/搜索等表现层。

## 10. 风险

- 中文谓词分类不稳定 → 规则+证据+人工抽样兜底；
- 关系召回低 → 两阶段候选 + 多轮 gleaning；
- 方向生成泛化 → 强校验（必须提到本节点概念）；
- 副本唯一序检测成本 → 3–6 步枚举可接受；
- 成本/延迟 → 每片段 1–2 次模型调用，控制在预算内；
- 旧数据迁移 → 现有 edges 可映射为 `related`，逐步补谓词。
