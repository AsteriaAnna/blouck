# 痛点梳理：节点准入、关系语义、副本出现时机

日期：2026-11-15
背景：真实语音输入暴露的问题
1. 节点不符合用户想表达的方向（例：开玩笑说"RAG 和灰姑娘一样都有悲惨的过去"，结果生成 RAG → 灰姑娘）；
2. 节点之间关系混乱，"包含"等关系理不清；
3. 副本出现规则不像游戏：不知道什么时候出现、出现的是不是"正确且自由度高"的副本。

本文用问题拆解，并给出规则修订方向。先不改代码。

---

## 一、Q&A：先用问题定位痛点

### Q1：这句话里，用户真正想学的是什么？

原话：

> "RAG 其实感觉和灰姑娘一样，都有一个悲惨的过去。"

- **话题主体**：RAG（用户正在学的概念）；
- **灰姑娘**：比喻的喻体（vehicle），不是用户要学的领域概念；
- **"悲惨的过去"**：用户的联想/类比内容，属于 RAG 的学习笔记，不是知识关系。

正确行为：

- 只建/更新 **RAG** 节点；
- 把"用户类比：RAG 像灰姑娘，都有悲惨的过去"写进 RAG 的节点 MD（或"类比"注释）；
- **不建灰姑娘节点**，不建 "RAG → 灰姑娘" 的正式关系；
- 如果用户后面明确说"我想比较 RAG 和灰姑娘的故事结构"，才把灰姑娘作为"跨域比较对象"引入。

痛点本质：**系统把"被提到的名词"都当成了"值得建节点的概念"**。

### Q2：什么算节点？什么不算？

节点不是"句子里的名词"，而是**用户学习对象 + 可解释 + 可出题**的概念。

建议的三道准入：

| 闸门 | 问题 | 不通过时 |
| --- | --- | --- |
| 意图/话题 | 它是这句话的话题主体，或是理解主体必需的下位概念吗？ | 喻体/例子/玩笑/口头语 → 笔记 |
| 可学习性 | 能给出定义、能出题、之后可能被继续学习吗？ | 只提一次、无定义、无关系 → 候选层或笔记 |
| 证据 | 有一句"关于它"的断言（不只是提到名字）吗？ | 不建节点 |

节点角色（新增，用于准入判断）：

| 角色 | 是否建节点 | 例子 |
| --- | --- | --- |
| `topic` 话题主体 | ✅ | RAG |
| `subconcept` 理解主体所必需 | ✅（有定义/证据时） | 分块、Rerank |
| `process` 过程/工作流本身 | ✅（步骤进副本） | 内容生产工作流 |
| `step` 过程步骤 | ❌（进流程副本） | 输入解析、审核发布 |
| `example` 举例 | ❌（进节点 MD） | "比如 BM25" |
| `metaphor` 比喻/类比 | ❌（进节点 MD） | 灰姑娘 |
| `noise` 口头语/玩笑/代词 | ❌ | 这个、那个、哈哈 |

### Q3：节点生成判断规则应该是什么？

1. 先从 episode 里抽"候选名词/过程"，不直接建节点；
2. LLM 给每个候选打角色 + 是否值得建 + 理由；
3. 程序校验：
   - 名词性（疑问句/动词短语/代词拒绝）；
   - 有证据句（关于它的断言，不是单纯出现）；
   - 领域/意图匹配（不在当前学习范围、也不是用户主动引入 → 笔记）；
   - 每 episode 新节点上限 3–5；
   - 重复/同义 → 归并（见 Q5）。
4. 比喻/例子/步骤统一进"笔记层"：
   - 节点 MD 的"类比/例子"区；
   - 不参与关系图、不参与副本、不出题。

### Q4：关系线到底表达什么？为什么"包含"理不清？

现在的问题：

- 谓词有 6 种，但界面只显示线，没有把"谁包含谁、方向是什么"讲清楚；
- `partOf`（部分→整体）和 `kindOf`（具体→上位）都容易被说成"包含/属于"；
- 模型有时把"整体→部分"也标成 partOf，方向反了；
- 比喻/举例也被当成 related 关系。

建议关系分类（知识关系 vs 非知识注释）：

| 关系 | 语义 | 方向 | 界面文案 | 是否进正式图 |
| --- | --- | --- | --- | --- |
| `kindOf` 归类 | A 是 B 的一种 | 具体 → 上位 | "A 属于 B 这一类" | ✅ |
| `partOf` 组成 | A 是 B 的一部分 | 部分 → 整体 | "A 组成 B / A 是 B 的一部分" | ✅ |
| `prerequisite` 前置 | A 在 B 之前 | 前置 → 后续 | "先学 A，再学 B" | ✅ |
| `contrast` 对比 | A 与 B 相对/不同 | 无方向 | "A 与 B 对比" | ✅ |
| `alternative` 替代 | A 可替代 B | 旧 → 新 | "A 替代 B" | ✅ |
| `related` 相关 | 明确断言的相关 | 无方向 | "A 与 B 相关（附证据）" | ✅（证据强） |
| `analogy` 类比 | A 像 B（比喻） | 无方向 | "类比：A 像 B" | ❌ 只进 MD |
| `example` 举例 | B 是 A 的例子 | 例子 → 概念 | "例如 B" | ❌ 只进 MD |

关键规则：

- **"包含"不是一种独立关系**：说"B 包含 A"时，若 A 是 B 的组成部分 → `partOf`（A→B）；若 A 是 B 的一个类别 → `kindOf`（A→B）；
- 关系必须有**证据句**，且证据要能推出这个谓词；
- 方向按谓词固定，证据中的语序只作为校验信号；
- 关系卡片显示："A —组成(部分→整体)→ B；依据：…；为什么是组成不是归类：…"；
- 比喻/举例不画正式线，放节点 MD 的"类比/例子"区（或极淡的注释标记，可关）。

### Q5：同义/近义概念怎么不重复？

- 精确名/别名 → 复用；
- embedding 相似 ≥0.9 → LLM 裁决 `same / parent_child / different`；
- `same` 合并别名/证据/定义（保留更长）；
- `parent_child` 建 `kindOf`，不合并；
- 合并保留 revision，可回滚。

### Q6：副本什么时候该出现？

"像游戏一样在合适的时间出现正确的副本"需要同时满足三类条件：

**A. 知识条件（正确性）**

- 流程：3–6 步、每步有证据、顺序唯一；
- 领域：≥4 个概念、有共同 `kindOf` 上位或共同来源；
- 成员/步骤未被隐藏、无争议。

**B. 玩家条件（可挑战）**

- 流程：过程节点 tier≥1；
- 领域：≥2 个成员 tier≥1；
- 或有明确前置链完成。

**C. 时机/节奏（游戏感）**

- 只在**自然停顿**出现：一段语音结束、一次答题结束、打开世界时；
- 不在用户正在输入/说话时弹；
- 冷却：同邻域 10 分钟；同类同时最多 1 个"新出现"；
- 每世界每类上限 3 个；
- 优先选择：与当前 focus 相关、最近活跃、未重复、novelty 高；
- **给玩家选择权**：同时最多展示 1–2 个候选；可"稍后再来/不再提示"；不强制弹窗；
- 同一副本不重复生成；通关后可重玩但不再重复"出现"。

### Q7：如何保证"自由度极高的副本"？

- 候选池：不同流程/领域可以同时存在，玩家自选进入；
- 难度/题型分层：同一副本可做基础/进阶（后续）；
- 允许"延迟/拒绝"：拒绝后冷却，不惩罚；
- 避免同质：同成员/同步骤指纹去重；领域重叠 ≤50%；
- 副本依据变化自动 stale，不硬塞过时内容。

### Q8：怎么验证规则真的有效？

- 节点：人工标注 20 段语音，统计"该建的建了、不该建的不建"（precision/recall + 误建类型）；
- 关系：谓词准确率、方向合法率、证据覆盖率；
- 副本：出现时机人工评审（是否打断、是否相关）、检测 P/R、通关率；
- 实时：episode 触发次数、延迟、每 episode 节点数。

## 二、当前实现的根因

| 痛点 | 根因 |
| --- | --- |
| 灰姑娘被建成节点 | 没有"节点准入"：LLM 抽到名词就建；没有 metaphor/example 角色；没有"话题主体 vs 喻体"判断 |
| 关系混乱 | 没有关系方向和界面解释；`partOf/kindOf` 语义接近；比喻被当 related；关系卡没有"为什么" |
| 副本时机不对 | 触发是"结构满足 + 邻域"的规则，不是"玩家状态 + 节奏 + 选择"；没有冷却/候选池/延迟机制 |

## 三、规则修订（建议直接写进生成算法 v3）

### 3.1 节点准入

```text
候选 → 角色判定 → 三道闸门 → 节点 or 笔记
角色：topic / subconcept / process / step / example / metaphor / noise
节点：topic、subconcept（有定义/证据）、process
笔记：example、metaphor、step（step 进流程副本）
拒绝：noise、疑问句、动词短语、代词
```

Prompt 要求每个候选输出：

```json
{ "name": "", "role": "topic|subconcept|process|step|example|metaphor|noise",
  "shouldBeNode": true, "reason": "", "evidence": "" }
```

### 3.2 关系准入

```text
候选关系 → 谓词分类 → 证据蕴含校验 → 方向归一 → 置信度 → 线型
知识关系：kindOf/partOf/prerequisite/contrast/alternative/related
注释关系：analogy/example（不画正式线，进节点 MD）
```

- 同对概念最多 2 种谓词；
- 无证据 → 不建；
- 证据不能推出谓词 → suggest 或拒绝；
- 方向按表归一；
- 关系卡必须展示"谓词 + 方向 + 依据 + 为什么不是另一类"。

### 3.3 副本出现

```text
score = 0.4 * knowledgeReady + 0.3 * playerReady + 0.2 * relevance + 0.1 * novelty
if score >= 0.7 and 冷却结束 and 当前无同类新出现:
    detected（出现，锁定）
```

- 出现后不打断输入；只在地图上出现建筑 + 提示；
- 玩家可"稍后再说"（冷却 30 分钟）或忽略；
- 可挑战条件满足后状态变 playable；
- 同指纹不重复；依据变化 → stale。
