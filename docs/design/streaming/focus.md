# focus / 多焦点

## 目标

每句话不是默认挂当前 focus，而是按证据选父节点；多句话、多分支、指代句能回到正确主题。

## 数据结构

服务端 SQLite：

```text
focus_stack(world_id TEXT PRIMARY KEY, stack TEXT JSON, updated_at)
```

栈是节点 ID 数组，最多 12 个；栈顶是当前主题，第二个是上一主题/兄弟主题。

## 选择顺序

```text
显式关系（属于/包括/分为/由…组成）
> 指代（它/这个/前者/后者）
> 文本提到的已有节点
> 当前 focus
> 上一句 focus
```

## 已实现

- `stream/session.ts` 的 `ingestSegment` 读取/更新 focus 栈；
- 新节点 parent 不再默认全部挂 focus；
- 一个句子创建多个节点时，兄弟节点也入栈，供下一句“前者/后者”使用；
- “后者”指向栈顶，“前者”指向栈第二；
- 关系 source/target 用同一个候选集解析，缺省不再直接用 focus。

## 验收

| 输入 | 结果 |
| --- | --- |
| RAG 包括检索和增强生成 | 检索、增强生成都挂 RAG |
| 检索分为稀疏检索和稠密检索 | 稀疏、稠密都挂检索 |
| 前者侧重关键词匹配，后者侧重语义匹配 | 关键词匹配→稀疏检索；语义匹配→稠密检索 |
| 混合检索属于检索 | 混合检索→检索 |
| RAG 还包括重排 | 重排→RAG |

## 未完成

- 指代只覆盖“它/这个/前者/后者/它们”，没有完整代词/省略恢复；
- focus 栈目前只存在服务端，前端没有展示栈状态；
- 多候选冲突时没有置信度排序；
- 关系端点仍依赖 LLM 输出，没有从候选集强制补全。
