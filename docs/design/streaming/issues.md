# 真实语音问题

真实测试已能出 provisional/节点，但还有四类问题。按层拆：

### 8.1 ASR 文本层：卡壳变逗号、后文不修正

现象：

- 说话卡壳/停顿，ASR 在那里打逗号；
- 逗号把一句话切成两段；
- 后面的内容不会把前面的逗号/切分改回来；
- 近似词被识别成常用词，但最终节点名有时又是对的。

第一性原因：

1. **流式 ASR 的标点由停顿/语言模型决定**，卡壳就是停顿；
2. **分段 final 只修正当前片段**，不重写之前已经显示的标点；
3. 没有"句级重写"：后一句来了，不会回头合并/修正前一句；
4. hotwords 只能提升词命中，不能保证标点/卡壳。

这不是建图错误，是 ASR 文本层问题。  
要解决需要：分段 final 后做一次局部重写（合并被逗号切碎的片段、纠正常用词、补标点），而不是只追加。

### 8.2 图状态层：ghost 位置 ≠ 最终节点位置

现象：

- 实时出现一个预测节点；
- 停止后预测节点消失，生成一个新节点；
- 新节点位置和预测位置不一样。

第一性原因：

1. ghost 位置是前端按 focus 临时算的；
2. 最终节点位置是后端 `placeAround` / 布局算的；
3. 两套位置没有共享；
4. 如果最终还重新建 ID/名字，ghost 就不是"同一个实体"。

这不是动画问题，是 **provisional 与 final 没有共享 ID/坐标**。  
正确做法：provisional 用最终布局的位置，或 final 保留 provisional 坐标；同一 ID 只做状态迁移，不重新建。

### 8.3 采集启动层：点了麦克风，要等一会儿才开始识别

现象：

- 点麦克风后开始说话；
- 前一段没有被识别；
- 过一会儿才开始出字。

第一性原因：

1. `getUserMedia` 要等权限/设备打开；
2. `AudioContext` / AudioWorklet 初始化；
3. `/ws/asr` 建连 + 豆包握手；
4. 在 `ws.onopen` 之前采集的 PCM 被丢弃（代码里 `wsRef` 未 OPEN 就 return）。

用户开口时，链路还没 ready，所以开头丢失。  
正确做法：先显示"准备中"，准备好再说；或先建 WS/ASR 握手，再开麦克风；或把 early audio 缓存到 ready 后发送。

### 8.4 关系层：城堡两边都连上了，但仍有卡壳

现象：

- 用"城堡"连接后妈和白雪公主，两边都建立了关系，方向/绑定基本可用；
- 但卡壳/标点会让端点名称错，导致关系挂错。

第一性原因：

- 关系绑定依赖 ASR 文本的端点名；
- 端点名错 → 关系端点错；
- 关系层本身没有"多候选/修正"机制。

### 8.5 三层问题不要混在一起

| 层 | 问题 | 归属 |
| --- | --- | --- |
| ASR 文本 | 标点、卡壳、近似词、后文不修正 | ASR + 文本后处理 |
| 图状态 | provisional/final ID/坐标不一致 | 前端/后端状态模型 |
| 采集启动 | 点麦克风到 ready 之间丢音频 | 浏览器采集/WS 时序 |
| 关系 | 端点名错导致挂错 | 关系绑定 + 实体纠错 |

### 8.6 处理方向

1. **ASR 文本后处理**：分段 final 后做局部重写/合并，不要只追加；结合停顿/标点/领域词纠正。
2. **共享 provisional 状态**：同一 ID、同一坐标；final 只做状态迁移，不重新建节点。
3. **启动预暖**：先建 WS/ASR，再开麦；或缓存 early audio，ready 后补发；UI 显示"准备中"。
4. **版本记录**：每次 ASR 修正/节点移动都记录 revision，便于回退。
