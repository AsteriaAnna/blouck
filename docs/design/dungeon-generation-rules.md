# 副本生成规则（v2）

日期：2026-11-14
状态：设计稿，待产品确认
依据：`docs/design/semantic-model-decision-2026-11-14.md`、`docs/design/generation-algorithm-v2.md`、两份基线文档
范围：流程副本 / 领域副本的识别、出现、可挑战、位置、题目、版本与评测

## 0. 先纠正上一版的错误

上一版副本规则的问题：

1. 用"formal 链 + 唯一拓扑序"就当流程——**一条链不等于一个过程**，可能只是几个相关概念；
2. 用"邻接簇"就当领域——**连在一起不等于同一领域**，没有共同上位概念/来源；
3. 引入 `node.role=步骤` 作为节点属性——**步骤是上下文角色，不是节点类型**：同一个概念在 A 流程里是步骤，在 B 里可能是组件；
4. 出现条件与可挑战条件混在 `locked/playable`；
5. 没有版本/失效处理（依据被争议、改名、隐藏后副本怎么办）；
6. 检测范围、去重、冷却、误报抑制都没定义。

下面按"学习意义"重写。

---

## 1. 设计原则

1. **副本必须由用户自己的理解长出来**：成员/步骤都能追溯到 SourceSpan，不是模型凭空编的课程；
2. **AI 负责"提出候选"，程序负责"硬校验"**：顺序唯一性、证据、粒度、命名都不能交给模型；
3. **出现 ≠ 可挑战**：先显示（detected），满足前置才能进（playable）；
4. **通关不删内容**：cleared 后保留，依据变化时标 stale，不静默覆盖；
5. **副本不参与节点/关系连通与方向判断**：它是练习层，不改知识结构。

---

## 2. 两个副本的语义边界

| | 流程副本 | 领域副本 |
| --- | --- | --- |
| 语义 | 一个**有先后顺序的同一过程/体系** | 一组**属于同一领域/类目**的概念 |
| 判定核心 | 过程证据 + 顺序唯一 + 粒度一致 | 共同上位概念或共同来源 + 领域命名 |
| 反例 | 只是相关概念链；多解流程；跨粒度步骤 | 只是连在一起的簇；没有共同类目；成员互相无关 |
| 玩法 | 排序连线（唯一正确顺序） | 每日 10 题（填空/判断/解答混合） |
| 是否影响三档 | 不影响节点三档 | 不影响节点三档 |

## 3. 流程副本

### 3.1 候选识别

触发：每次抽取后，只对**新增节点 + 1–2 跳邻域**做检测（不扫全图）；同一世界单任务、500ms 去抖。

LLM 输出候选（结构化）：

```json
{
  "isProcess": true,
  "processName": "RAG 检索流程",
  "stepConcepts": ["文档分块", "向量检索", "重排", "生成回答"],
  "order": ["文档分块", "向量检索", "重排", "生成回答"],
  "evidencePerAdjacentPair": [
    "先把文档切成分块，再做向量化",
    "检索出候选后，用 Rerank 重排",
    "重排后的结果交给大模型生成回答"
  ],
  "processEvidence": "整段话在描述同一条问答链路",
  "confidence": 0.86
}
```

要求模型回答：**这是不是一个同一过程？为什么顺序是这样？每一步的来源句是哪句？**

### 3.2 硬校验（全过才 `detected`）

| # | 校验 | 说明 |
| --- | --- | --- |
| 1 | 步骤数 **3–6** | 少于 3 不是流程；多于 6 粒度失控 |
| 2 | 每个相邻步骤有**过程证据** | 必须命中"先/再/然后/最后/之后/接着/第一步/再交给/最后输出"等过程词，或明确的因果/依赖句 |
| 3 | **唯一拓扑序** | 用相邻约束枚举所有合法顺序；合法顺序数 ≠ 1 → 拒绝（多解流程不硬判） |
| 4 | 无环 | 约束图有环 → 拒绝 |
| 5 | 每步都有 SourceSpan | 无来源的步骤拒绝 |
| 6 | 粒度一致 | 每步都是"阶段级"概念；出现"子步骤混入"（如某步是另一步的细节）→ 拒绝 |
| 7 | 成员未被隐藏/争议 | hidden 或 claim_status=disputed 的节点不进入副本 |
| 8 | 过程名合法 | 2–12 字、不与已有副本重名、不是泛词（"流程/系统/方法"单独不算） |
| 9 | confidence ≥ 0.75 | 低于阈值不出现 |

**额外语义校验**：整个过程的每一步必须能在同一段/相邻两段 SourceSpan 中找到依据；跨多个不相干片段的拼接 → 拒绝。

### 3.3 反例（必须拒绝）

- "RAG → 检索 → 精排"：只有相关性，没有先后证据；
- 用户只说了 2 步；
- 用户描述了一个多解过程（"可以先 A 也可以先 B"）；
- 步骤里混入"提示词工程"这种跨粒度概念；
- 只由 suggest 虚线连接的概念（未确认关系不能作为流程依据）。

### 3.4 状态机

```text
candidate（内部） → detected（出现，锁定显示） → playable（可挑战） → cleared（通关）
                                              ↘ stale（依据变化，提示待更新）
```

- **detected**：硬校验通过即出现；建筑显示"未解锁"和依据说明；
- **playable**：链上**每个步骤节点当前 tier ≥ 1**（按基线"相关节点当前有效第一档均达成"）；
- **cleared**：排序完全正确；保存通关记录，建筑保留可再次打开；
- **stale**：成员被隐藏/改名/争议/删除依据后，标记"依据待更新"，不重置历史通关，也不允许作为当前资格。

### 3.5 玩法与判题

- 展示打乱后的步骤（概念名），用户按顺序点击连线；
- 判定：只接受**唯一正确顺序**（校验时已经保证唯一）；
- 失败不升级、不扣节点进度；可以重试；
- 通关后展示每步依据句（来自 SourceSpan），副本 MD 可编辑；
- 副本 MD 不被重新生成覆盖；重算只更新 `stale` 标记。

### 3.6 触发与去重

- 指纹 = `sorted(stepIds)`；同指纹只生成一次；
- 同一世界流程副本上限 3；
- 新副本出现有冷却：同一邻域 10 分钟内不重复检测；
- 用户手动关闭？不做；只标记 stale/hidden（后续）。

### 3.7 参数

| 参数 | 起始值 |
| --- | --- |
| 步骤数 | 3–6 |
| 相邻步骤过程证据 | 必须 |
| 唯一拓扑序 | 必须 |
| 每步来源 | 必须 |
| 候选 confidence | ≥0.75 |
| 检测半径 | 2 跳 |
| 每世界上限 | 3 |
| 冷却 | 10 分钟/邻域 |
| 可挑战：每步 tier | ≥1 |

## 4. 领域副本

### 4.1 候选识别

LLM 输出：

```json
{
  "isDomain": true,
  "domainName": "检索技术",
  "members": ["BM25", "向量召回", "混合检索", "Rerank"],
  "commonBasis": "都服务于检索/排序",
  "evidence": "这一段都在讲检索的召回与排序",
  "confidence": 0.8
}
```

要求模型回答：**这些概念为什么属于同一领域？领域名是什么？**

### 4.2 硬校验（全过才 `detected`）

| # | 校验 | 说明 |
| --- | --- | --- |
| 1 | 成员数 **≥4** | 少于 4 不构成领域；上限 8 避免过泛 |
| 2 | **共同上位概念或共同来源** | 所有成员都有指向同一上位概念的 `kindOf`，或 ≥3 个成员共享同一 SourceSpan；只有"互相连边"不够 |
| 3 | 领域命名合法 | 2–12 字、不是成员名本身、不是泛词（"AI/技术/知识"单独不算）、不与已有领域重名 |
| 4 | 成员都有 definition + evidence | 没有定义/来源的成员不进入 |
| 5 | 无 hidden / disputed 成员 | 争议或隐藏节点不作为依据 |
| 6 | 领域重叠控制 | 与已有领域副本成员重合度 ≤ 50% |
| 7 | confidence ≥ 0.7 | 低于阈值不出现 |

### 4.3 反例（必须拒绝）

- 一组只是被 suggest 虚线连起来的概念；
- 成员里混入"提示词/上下文窗口"等跨领域概念；
- 领域名与成员同名（"Rerank 领域"）；
- 只有 2–3 个概念；
- 已有领域副本成员重合 80%。

### 4.4 状态机

```text
detected（出现，锁定） → playable（相关节点 ≥2 个当前 tier≥1） → cleared（当日/累计）
                        ↘ stale（依据变化）
```

- 建筑出现在锚点节点旁（锚点 = 成员中度数最高者）；
- **出现不等于可挑战**；锁定状态显示"相关节点至少 2 个达到第一档"。

### 4.5 每日题目规则

- 按 **用户 + 世界 + 领域 + Asia/Shanghai 自然日** 计额：每日 10 道新题；
- 首次打开生成当日题组，逐题占用名额；重答原题不占新名额；刷新/退出继续同一组；跨天生成新组；
- 题型混合（示例比例）：填空 4 / 判断 3 / 解答 3；
  - 填空：标准答案 + 可接受别名，本地判定；
  - 判断：本地判定；
  - 解答：AI 判定（保留理由）；
- 每题必须引用**成员概念 + 证据句**；依据争议/失效的题不进入当日题组；
- 领域题**不计入节点三档**；只记录领域练习进度；
- 用户可随时退出，不强制做满 10 题。

### 4.6 触发与去重

- 指纹 = `sorted(memberIds)`；同指纹不重复生成；
- 每世界领域副本上限 3；
- 与流程副本互不替代（同一组概念可以既有流程又有领域，如果语义都成立）。

### 4.7 参数

| 参数 | 起始值 |
| --- | --- |
| 成员数 | 4–8 |
| 共同上位/共同来源 | 至少满足一个 |
| 重叠度上限 | 50% |
| 候选 confidence | ≥0.7 |
| 每日新题 | 10 |
| 题型比例 | 填空4/判断3/解答3 |
| 可挑战：tier≥1 节点数 | 2 |
| 每世界上限 | 3 |

## 5. 位置与呈现（3D）

**核心要求：副本要出现在相关概念节点的旁边或中间，但不能粘连，四周要留空间。**

| | 流程副本 | 领域副本 |
| --- | --- | --- |
| 锚点 | 链首概念节点 | 领域上位概念（`commonParent`）；没有则取成员中度数最高者 |
| 相关集合 | 链上全部步骤 | 领域成员 + 上位概念 |
| 位置基准 | 相关节点中心点的质心 | 同上 |
| 3D 造型 | 门（gate）+ 台阶 | 塔（tower）+ 地标 |
| 状态 | 未解锁/可挑战/已通关/依据待更新 | 同上 |
| 点击 | 打开副本抽屉（步骤排序 / 每日题组 / MD） | 同上 |

### 5.1 摆放算法（已实现）

坐标约定：节点 `n.x/n.y` 是 190×170 视框左上角，中心 `(n.x+95, n.y+85)`；副本 `b.x/b.y` 是中心，按 200×190 处理。

1. 计算相关集合的质心 `C`；
2. 以 `C` 为圆心，半径 `[230, 280, 340, 410, 500, 620]` × 16 个方向采样候选点；
3. **留白约束**（AABB 外扩）：
   - 副本与任一节点至少留 `55` 像素空隙（同一轴）；
   - 副本与副本之间至少留 `70` 像素；
   - 不满足直接丢弃；
4. 打分：`-距离质心 * 0.25 + min(留白, 120) * 0.35`；
   - 越靠近相关节点越好（旁边/中间），留白越大越好，但留白收益封顶，避免被"甩远"；
5. 全部候选不合格时，选留白最大的候选兜底；
6. 结果写入 `buildings.x/y`；之后重排布局只在发生碰撞时重新放置。

### 5.2 实测（副本测试世界）

- 流程副本：4 步链，放在链上方的质心旁，与最近节点留白 **100**；
- 领域副本：上位概念 + 4 成员，放在簇下方，与最近成员留白 **116**；
- 两副本之间留白 **1320**，不粘连、不遮挡标签。

副本不参与方向线的 frontier 计算，也不作为隐藏连通依据。

- `server/src/assetops.ts`：`ensureBuildingPositions` 已按上述规则重写；
- `POST /api/dev/dungeon-fixture`：构造必然触发流程/领域副本的世界，用于验证检测与位置；
- 截图：`docs/screenshots/12-dungeon.png`（流程副本在链上方、领域副本在簇下方，均留空隙）。

## 6. 与节点 / 关系 / 方向的关系

- 只用**正式关系**（formal）与 SourceSpan 作为依据；suggest、direction、来源线不参与副本判定；
- 成员/步骤必须已存在为概念节点，不能为副本临时造节点；
- 不改变节点三档；方向生成不受副本影响；
- 副本依据的节点/关系被争议/修订 → 副本 `stale`，暂停出题，历史通关保留。

## 7. 评测（副本专项）

在 `server/eval` 增加副本用例：

**流程**
- 正例 5：清晰 3–6 步过程，有过程词与来源；
- 负例 5：只有相关链 / 2 步 / 7 步 / 多解 / 跨粒度 / 无来源 / 争议成员。

**领域**
- 正例 5：共同上位概念或共享来源的 ≥4 概念；
- 负例 5：随机连通簇 / 3 个概念 / 无共同类目 / 泛领域名 / 与已有领域高度重叠。

指标：

| 指标 | 目标 |
| --- | --- |
| 流程检测 Precision / Recall | ≥0.8 / ≥0.7 |
| 流程唯一序正确率 | 100%（校验后） |
| 领域检测 Precision / Recall | ≥0.8 / ≥0.7 |
| 题目依据覆盖率 | 100% |
| 误报率（负例被生成） | ≤10% |

## 8. 实施顺序

1. 数据模型：Dungeon(version/basis/status/fingerprint)、DungeonMember、DungeonQuestion、DailySet；
2. 流程候选 LLM + 唯一序校验器（枚举约束图）；
3. 领域候选 LLM + 共同上位/来源校验；
4. 状态机与 stale 机制；
5. 领域混合题型 + 日额；
6. 副本专项评测。
