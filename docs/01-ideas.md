# 01 · 之前讨论过的设想

> 这是历史记录，不是实现依据。
> 当前代码实际采用的范围见 [03-implemented.md](03-implemented.md)；不要根据本文判断某功能存在，也不要据此直接开工。

## 产品方向

- 把口头/文字输入变成可探索的知识地图；
- 知识以节点 + 关系表达，地图是 3D 岛屿世界；
- 节点可以有题库、方向、副本、隐藏/撤回；
- 语音输入要尽量“言出法随”，边说话边出现候选节点；
- 用户说完后，候选变成正式节点，探索可以继续。

## 架构方向

- 前端 React + 3D 渲染；
- 服务端负责抽取、关系、布局、持久化；
- LLM 负责从自然语言抽实体/关系；
- ASR 负责把语音变成文本；
- 文本进来后先形成 provisional，再 commit 成正式图。

## 交互方向

- 一句话可以有多个新节点；
- 多句话、多分支要能回到正确主题；
- 关系要能连到已有节点，而不是全挂当前焦点；
- 语音出错时，候选可以先出现，之后修正；
- 微信语音输入那种“边说边修”是体验参考。

## 明确的边界

- 这些只是方向，不是需求清单；
- 具体哪些已经实现，只看 03 和代码；
- 03 没写的，不要假设存在。
