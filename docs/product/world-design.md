# 知识世界 v3：设计、机制与展示口径

> 状态：2026-11-18。本文只写“用户看到什么、为什么这样设计、什么算成立”，不写数据库字段和函数名。
> 实现事实见 [implemented.md](../engineering/implemented.md)，偏差审计见 [design-gap-audit.md](../engineering/design-gap-audit.md)。

## 0. 三条硬原则

1. **图谱不是知识本身，是理解的脚手架。**  
   节点/关系可以来自 AI 或用户，但只有能回指原文的才叫“事实关系”；否则只能是“假设/方向”。

2. **线必须有意义。**  
   一条线要么帮助用户理解结构（关系），要么告诉用户下一步（方向），要么记录来路（序列），要么提示可能但未确认（提示）。做不到就不画。

3. **题不是复习，是辨析。**  
   题必须让用户比较、判断边界、解释理由；不能是“什么是 X”的定义默写。

## 1. 视觉层：世界地图

### 1.1 空间语言

| 视觉对象 | 含义 | 用户动作 |
|---|---|---|
| 浮岛 | 一个知识节点 | 点击打开节点卡 |
| 岛上的地标/小模型 | 节点类型（概念/方法/组件/指标/工具） | 无 |
| 岛的层级/环 | 理解档位 tier | 答题/辨析后变化 |
| 粗实线 | **关系线**（已确认的语义关系） | 点击打开关系卡 |
| 实线+箭头 | **序列线**（这一步从哪来） | 点击看来源 |
| 虚线+路牌 | **提示线**（可能有关，待确认） | 点击确认/忽略 |
| 点线+光点+路牌 | **方向线**（下一步可以探索什么） | 点击探索，生成节点 |
| 塔 | 领域副本（一组概念的辨析/练习） | 点击进入副本 |
| 门 | 流程副本（步骤排序/流程理解） | 点击进入副本 |

地图默认克制：提示只显示 top 2，方向只显示 2 条；拉近显示更多；用户可手动展开全部。

### 1.2 什么不显示

- 不显示置信度、版本号、内部 id、模型名、token 数。
- 不显示没有证据的“关系断言”。
- 不把“方向问题”画成关系线。
- 不在节点卡里堆所有邻居；只显示能解释“它和谁、什么关系、为什么”的少量结构。

## 2. 内容层：MD 卡格式

### 2.1 节点卡（理解卡）

用户点开节点必须看到：

```text
定义：一句话说清它是什么
体系位置：
  · 邻居 A — 关系类型（方向：A→本节点 / 本节点→A）
  · 依据：原文引用（没有就写“暂无来源，不足以判断题”）
边界：它不是什么 / 容易和谁混
来源：来自哪段原文 / 哪次输入
下一步：可探索的具体问题（不是空泛的“继续深入”）
我的笔记：用户可编辑
辨析任务：边界/反例/纠错/迁移之一，带原文引用、理由输入、rubric
```

**硬规则**：

- 没有 `source_span` 的节点可以存在，但只能显示“假设/待补来源”，不能生成“事实题”。
- 节点卡上的关系必须带 canonical predicate（kindOf/partOf/prerequisite/contrast/alternative/related）和方向。
- “related”只能用于“原文明确说两者相关但无法判断更强类型”，不能当默认填充。

### 2.2 关系卡（对照卡）

用户点开一条关系必须看到：

```text
一句话：A 相对 B 是什么
关系类型 + 方向：kindOf / partOf / prerequisite / contrast / alternative / related
依据：原文句（必须是源文本子串；没有就显示“缺少依据，这条线只是假设”）
辨析：
  · 相同点
  · 不同点
  · 边界
  · 反例/易混
我的笔记
关系辨析任务（选择 + 理由 + 原文引用）
```

**硬规则**：

- 正式关系（实线）必须有原文依据；没有依据只能是虚线提示或“假设”，不能升级为正式关系。
- 关系类型必须来自固定枚举，不能只显示“依赖/组合/使用/技术关联”这种自由标签。
- 关系方向由 predicate 固定：kindOf 具体→上位；partOf 部分→整体；prerequisite 前置→后续。
- **反例**：把“向量数据库”和“上下文窗口”硬连成 related，且证据写“证据未显示…故定位为相关”，这是把模型的推理说明当证据，必须禁止。

### 2.3 副本 MD

副本不是另一套知识，而是把已有关系组织成可玩的单元：

```text
这个副本考什么：哪个误解 / 哪组易混概念
成员/步骤：从哪些节点、哪些关系来
依据：原文引用
关卡：基础/强化，题型序列
通关条件：全部关卡答对，而不是刷题数量
```

## 3. 机制层

### 3.1 四类线的状态

| line_type | line_state | 含义 | 点开是什么 |
|---|---|---|---|
| relation | confirmed | 已确认语义关系，有证据 | 关系卡 + 辨析任务 |
| relation | hypothesis（待建设） | 用户/AI 假设但无证据 | 只显示“假设”，不能出事实题 |
| sequence | recorded | 新节点的生成来路 | 来源说明，不是知识关系 |
| hint | candidate | 可能有关，待确认 | 提示卡：确认（需补证据）/忽略 |
| exploration | open / consumed | 下一步问题 | 方向卡：去探索 / 已消费 |

### 3.2 点开以后有什么

- **关系线**：关系卡（定义、类型方向、证据、辨析、反例、笔记、任务）。
- **序列线**：来路卡（哪次输入、哪句、生成顺序），不提供“关系断言”。
- **提示线**：候选卡（为什么觉得有关、证据有没有、确认/忽略）。
- **方向线**：方向卡（问题、目标节点预览、去探索）；探索后变关系线或序列线。
- **节点**：节点卡 + 辨析任务 + 复习模式（旧定义题，可选）。

### 3.3 题从哪里来

| 题型 | 输入 | 生成 | 展示 | 不展示 |
|---|---|---|---|---|
| 节点辨析 | 节点来源原文 + 邻接关系 | 边界/反例/纠错/迁移，选择+解释 | 题干、依据、选项、理由、追问 | 正确答案、内部评分 |
| 关系辨析 | 关系证据原文 + 两端定义 | 类型/方向/边界/反例/迁移 | 同上 | 同上 |
| 副本关卡 | 关系证据原文 + 易混关系 | 基础 3 关 / 强化 4 关 | 关卡序列、进度、反馈 | 正确答案 |
| 旧定义题 | 节点定义/来源句 | short/judge | 仅在“复习模式”折叠里 | 不作为主路径 |

**硬规则**：

- 没有原文证据 → 不出事实题；只能提示“补来源”。
- 题必须带 `evidence_quote`，且能在 source_span 中找到。
- 低质量题（可抄定义/无干扰项/无比较）不进入副本。
- 题目答案不下发前端。

### 3.4 副本出现机制（目标设计）

副本不是“抽出第一个图就出现”，而是**世界长到一定程度、方向已经出现后，才被发现**：

```text
节点积累到阈值
→ 出现可探索方向（至少一个 open direction）
→ 方向/关系中有足够的证据关系
→ 系统检出“领域/流程候选”
→ 副本以“已发现/未解锁”出现
→ 用户通过辨析/答题让相关节点达到档位
→ 副本变为可挑战
→ 通关后 cleared
```

判定条件（建议）：

- 可见节点 ≥ 8；
- 有证据的正式关系 ≥ 4；
- 至少 1 个 frontier 节点（可继续探索）；
- 领域候选 ≥ 4 个成员/同一上位；流程候选 ≥ 3 步且有先后证据；
- 不在第一次输入就出现。

## 4. 需求 vs 解决方案

| 需求（为什么） | 解决方案（怎么做，可替换） |
|---|---|
| 世界要看起来在生长，而不是节点堆叠 | 序列线、来路、动画；用 direction/source 表/字段实现 |
| 用户永远知道下一步 | 每节点 4 条方向；地图只显示 1–2 条；节点卡列出全部 |
| 关系必须可信 | 证据门 + canonical predicate + 无证据只能是假设 |
| 题要增加理解，不是复习 | 辨析任务（对比/边界/反例/迁移），带 rubric/解释评分 |
| 副本要像“发现了一个新区域” | 累积阈值 + 方向出现 + 关系证据 + 解锁状态 |
| 副本要好玩 | 基础/强化、误解序列、通关反馈；不是 10 道定义题 |
| 用户能纠正系统 | 好/差反馈、接受/忽略提示、手动关系、备注 |

> 任何实现选择（表、路由、LLM、动画）都只是解决方案；不能反过来定义需求。

## 5. 当前未决问题（需要产品确认）

1. 没有证据的关系是否允许以“假设线”存在？还是只允许后台候选、不画地图？
2. 节点档位主要由辨析驱动，旧定义题是否完全退出主路径？
3. 副本发现阈值是否按“节点数 + 证据关系数 + open direction”三项？是否需要用户手动触发检测？
4. 关系类型是否只保留 6 类；不再允许“依赖/组合/使用/技术关联”这类自由标签作为主显示？
5. 方向探索生成的新节点，是否强制先预览目标节点再落图？
