# 关系绑定

> 状态（2026-11-16）：本文是设计草案，**没有逐条经用户确认**。
> 9.1/9.2 是观察；9.3 里只有"候选集 + 证据方向 + commit 正式化"与 MVP 直接相关，
> relation ID/lifecycle、多谓词上限、冲突修订属于未来假设，不是已确认需求。

### 9.1 场景

图谱里原本已有 3 个节点：

```text
A = RAG
B = 检索
C = 增强生成
```

用户继续说：

```text
混合检索属于检索，召回率衡量增强生成。
```

新节点：混合检索、召回率。

期望：

```text
混合检索 --kindOf--> 检索        （新 → 已有）
召回率   --related(衡量)--> 增强生成 （新 → 已有）
来源父链：混合检索 ← 检索；召回率 ← 增强生成/Re-ranking
```

这里有三层绑定，之前只做了第一层：

1. **mention → node**：这句话的"检索"是已有 B，不是新节点；
2. **subject/object**：混合检索是 subject，检索是 object；不能默认 focus；
3. **relation → edge**：谓词、方向、证据、状态，绑定成一条可追踪的关系。

### 9.2 之前的方案够不够

| 能力 | 之前方案 | 是否够 |
| --- | --- | --- |
| 新节点有稳定 provisional ID | 有 | ✅ |
| 已有节点本地匹配 | 有 | ✅ |
| 新节点父链/来源 | 有 | ✅ |
| 关系目标覆盖已有节点 | 没有 | ❌ |
| subject/object 角色判定 | 没有 | ❌ |
| 关系 edge 的稳定 ID/生命周期 | 没有 | ❌ |
| 多关系/多已有节点并存 | 没有 | ❌ |
| 已有正式关系的修订规则 | 没有 | ❌ |

**结论：之前方案能解决"节点从哪来"，不能解决"新节点和已有节点怎么绑关系"。**

### 9.3 需要补的：关系绑定层（设计草案，未确认）

#### MVP 取舍

| 内容 | MVP 是否必须 | 理由 |
| --- | --- | --- |
| 候选集（focus + 本句已有节点） | 是 | 否则关系只挂 focus |
| 证据判 subject/object | 是 | 否则方向靠猜 |
| commit 时 suggest→formal | 是 | 否则关系永远虚线 |
| relation 稳定 ID/lifecycle | 否 | 当前没有合并/撤回/重命名流程 |
| 同一对节点最多 2 谓词 | 否 | 产品规则未验证 |
| formal 冲突 disputed/revised | 否 | 当前没有修订入口 |
| 图谱邻居/top-k 候选 | 否 | 9.4 场景用 focus+本句已够 |


#### 1. 关系候选不只对 focus

每个新节点生成候选：

```text
候选对象 = 当前焦点
         + 本句提到的已有节点
         + 本句新节点
         + 图谱邻居 / 语义 top-k 已有节点
```

不是"只看 focus"。

#### 2. 用证据定 subject/object

- 证据句里谁在前、谁在后；
- 显式句式："A 属于 B" → A→B；"B 包含 A" → A→B；
- 不能默认 `source=focus`；
- 方向按谓词表归一。

#### 3. 关系要有稳定 ID

```text
relationId, subjectProvisionalId, objectProvisionalId,
predicate, evidence, confidence,
status: candidate | suggest | formal
```

- provisional 节点合并 → relation 重新绑定；
- provisional 节点失败 → 关系撤回；
- 正式关系不可删除，只能 dispute/revise。

#### 4. 多关系并存

- 新节点可以同时有来源父链 + 多条知识关系；
- 同一对节点最多 2 种谓词（产品规则）；
- 不确定关系 → suggest，不静默丢。

#### 5. 已有节点关系不能被新关系覆盖

- 已有 formal 关系不可删；
- 新证据冲突 → claim_status=disputed/revised；
- 不能因为新节点生成，把旧关系替换掉。

### 9.4 验收场景（新增）

```text
已有：A=RAG，B=检索，C=增强生成
输入：混合检索属于检索，召回率衡量增强生成。
期望：
  混合检索 kindOf 检索
  召回率 related(衡量) 增强生成
  两条关系都有证据
  不允许两条都挂 A/RAG
```

再补一条：

```text
输入：混合检索由语义检索和向量检索组合而成。
期望：
  混合检索 related(组合) 语义检索/向量检索
  不把语义检索/向量检索挂到 RAG
```

### 9.5 参考

| 环节 | 参考 | 能帮什么 |
| --- | --- | --- |
| mention → 已有节点 | [Entity Linking survey](https://dl.acm.org/doi/10.1145/3795134) | 实体链接/消歧 |

没有现成"教学图关系绑定"实现；这层必须自研。


### 9.6 真实流式语音验证（2026-11-16）

链路：`/ws/asr` 真实豆包 ASR + 16k PCM WAV（Huihui TTS）；图初始 3 节点：RAG、检索、增强生成。

| 语音 | ASR 文本 | 结果 |
| --- | --- | --- |
| 混合检索属于检索 | 正确 | `混合检索 --kindOf--> 检索`；父节点检索 |
| 召回率衡量增强生成 | 正确 | `召回率 --related--> 增强生成`；父节点增强生成 |
| 今天天气不错… | 正确 | `[skip]`，不建节点 |
| 混合检索由语义检索和向量检索组合而成 | **语义/向量 → 羽翼/项梁** | 结构正确（两新节点 partOf 混合检索），但实体名错 |
| 四句连续语音 | 多句粘连，final 只回第一句 | 多句建图失败 |

结论：

1. **关系绑定结构在单句真实语音上可行**：新→已有、新→新都能挂；
2. **ASR 术语识别是当前最大卡点**：语义/向量被识别成羽翼/项梁；
3. **多句连续语音分段/final 仍失败**：当前豆包 ASR 接法只适合单句，或需要改 final 累积；
4. 所以"真实语音 + 多跳关系绑定"还不能算通过；卡点在 ASR 文本质量，不在绑定规则。

下一步：

- 换支持热词的 ASR 接口，或加领域词纠错；
- 修多句 final 累积；
- 再用同一脚本复测。
