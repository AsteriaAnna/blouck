# 02 · 尝试过的思考方式和推断过的措施

> 历史记录，不是实现依据。
> 这里记录的是“当时怎么想/怎么试”，不代表代码里现在有这些做法。当前实现见 [03-implemented.md](03-implemented.md)。

## 1. 只保留单 focus

- 早期推断：每句话只有一个当前焦点，新节点都挂 focus。
- 结果：多分支/多句话会挂错父节点。
- 现状：这个做法没有作为最终方案采用。

## 2. 前端 ghost 和最终节点分开

- 早期推断：先在前端画 ghost 预览，final 后重新 `/extract` 生成正式节点，再用动画衔接。
- 结果：ghost 和 final 是两套 ID/坐标体系，会产生“候选消失、位置跳变”。
- 现状：这个做法没有作为最终语音链路采用。

## 3. 把 ASR 的 definite 当成整段结束

- 早期推断：收到 definite / flags&2 就认为用户说完了，直接 final。
- 结果：用户还没停止就结束录音，多句丢失。
- 现状：没有采用；现在 definite 只作为句子 `segment`。

## 4. 强制 AudioContext 为 16k

- 早期推断：直接创建 16000Hz AudioContext，最省事。
- 结果：麦克风原生 48k，降采样质量/相位/浏览器行为不稳定。
- 现状：没有采用；现在用原生采样率 + AudioWorklet 重采样。

## 5. 主线程逐块重采样

- 早期推断：Worklet 只转 Float32，主线程每块线性插值到 16k。
- 结果：块间相位断裂，PCM 电音；主线程二次解释 Int16 时直接坏掉。
- 现状：没有采用；现在重采样在 Worklet 内连续相位完成。

## 6. 完整关系生命周期

- 曾推断：relation 要有稳定 ID、candidate/suggest/formal 生命周期、冲突 disputed/revised、同一对节点最多 2 谓词。
- 结果：这些是讨论/草案，不是当前代码。
- 现状：没有进当前实现，不要当成已有能力。

## 7. 文本重写与启动预暖

- 曾推断：ASR 卡壳逗号要局部重写；麦克风启动前要预暖/缓存早期音频。
- 结果：这些是问题记录，不是当前代码。
- 现状：没有进当前实现。

## 8. anchor-first 实验

- 曾写过一个 anchor-first 的实验路径和 `/stream/preview` 预览接口。
- 结果：不是当前语音正式链路。
- 现状：代码里可能仍保留实验文件，但不要把它当主链路。
