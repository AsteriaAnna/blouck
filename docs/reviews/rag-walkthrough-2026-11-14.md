# RAG 逐句验收记录（2026-11-14）

方式：新世界，初始节点「RAG」，逐句输入 6 段材料；每步检查节点、关系、方向、副本；最后点击节点/副本。
环境：DeepSeek 真实抽取 + 当前前端/后端。

## 输入序列

1. RAG 先把文档切成分块，然后做向量化存进向量数据库。
2. 用户提问时，先从向量数据库检索相关分块，再交给大模型生成回答。
3. 混合检索把 BM25 的关键词召回和向量数据库的语义召回合并，然后用 Rerank 精排。
4. 评测要看召回率和准确率，还要做事实一致性检查。
5. 工作流会依次做输入解析、检索资料、生成草稿、审核发布。
6. RAG 和微调不同：RAG 不改模型参数，适合经常变化的知识。

## 结果（修复后）

- 17–19 个节点，全部有 type/definition/source_span；
- 关系 47–54 条：source 来路 + formal/suggest 语义关系 + direction；
- **孤儿节点 0**、非方向自环 0、正式关系缺证据 0；
- 方向：LLM 生成，例如"混合检索中 BM25 与向量召回结果如何加权合并？"；
- 副本：
  - 流程 `RAG 文档处理流程`（分块 → 向量化 → 向量数据库）`detected`；
  - 第二个流程（工作流 4 步）也能生成，不再一个世界只允许一个；
  - 领域：需要用户明确说"X、Y、Z 都属于检索技术"时生成 `检索技术 · 领域副本`（BM25/向量召回/混合检索/Rerank），与"组成部分"区分；
- 点击节点：抽屉能取到类型/定义/题库接口/方向；
- 点击副本：`challenge` 返回 409（detected，未达 tier 条件），符合"出现 ≠ 可挑战"。

## 这轮发现并修复的问题

| # | 问题 | 修复 |
| --- | --- | --- |
| 1 | 领域校验把"共同邻居"和 label 含"属于"当共同上位，导致把 RAG 的组件误判为"RAG 核心组件 · 领域副本" | 只认 `predicate=kindOf`（或 predicate 为空且 label 明确"归类"）；"仅仅共同邻居不算领域" |
| 2 | `toDungeonEdges` 丢掉 predicate，领域候选永远生成不了 | 适配器补 `predicate` |
| 3 | 模型返回 suggest、但证据充分/置信度≥0.75 的关系仍是虚线 | 证据+置信度足够时升级为 formal |
| 4 | 前置关系方向反了（如 Rerank → 混合检索） | 按证据中实体出现先后归一：前置 → 后置 |
| 5 | 组成关系出现"整体 → 部分"（RAG → 分块） | label 含"组成/包含/由"时换成"部分 → 整体" |
| 6 | 每世界只能生成一个流程副本 | 每类最多 3 个，按指纹去重 |
| 7 | 非边缘节点仍残留方向线数据 | 物化方向线时清理非 frontier 的方向边 |
| 8 | LLM 流程名过短/等于焦点名（出现标题"RAG"） | 名称 <3 字或等于焦点名时回退为「首步名 + 流程」 |

## 仍需注意

1. 节点名仍有动词短语（"审核发布""生成草稿"），类型被归到"方法"；下一步需要名词化规则（例如追加"环节"）或让模型输出名词化名称；
2. 领域副本依赖用户显式说"属于某类"；只描述组成关系时不会生成（这是精度优先的取舍）；
3. 关系方向归一目前是启发式（证据出现顺序/组成关键词），多实体、否定句、并列句仍可能误判；
4. 节点题库未生成（tier=0 时未点"生成题库"），副本因此停留在 detected；
5. 流程唯一序、领域日题组逻辑已实现，但还没在真实 UI 里点完整流程。

## 结论

"RAG 为第一个词、逐句输入"的链路现在是通的：节点有意义、关系有谓词和证据、方向由 LLM 生成、副本能区分流程/领域且不会把组件当领域。剩余主要是名词化和方向归一化的精度问题。


## 第二轮补齐（2026-11-14 晚）

### 节点/步骤的语义单位（修正）

之前把“输入解析/检索资料/生成草稿/审核发布”各自补“环节”再建节点，是**错的**：这是在字符串层面猜词性，不是理解句子。

正确规则：

- 一句话在描述一个**过程/工作流**时，只抽“过程本身”作为节点（如 `RAG 内容生产工作流`）；
- 步骤属于这个过程的**流程副本**，不建节点；
- 只有用户单独把某个步骤当作学习对象时，它才可能成为节点。

验收：输入“工作流会依次做输入解析、检索资料、生成草稿、审核发布。”

结果：

- 节点：`RAG(概念)` / `RAG 内容生产工作流(概念)` —— 只有两个，没有 4 个“环节”节点；
- 流程副本：`RAG 内容生产工作流`，步骤 `输入解析 → 检索资料 → 生成草稿 → 审核发布`；
- 流程节点答对 1 简答 + 1 判断 → tier=1 → 副本 playable；
- challenge 返回打乱的步骤名；提交正确顺序 → cleared。

### 节点 AI 自动生成题目

- 抽取后对最多 3 个新节点后台生成题库；
- 打开节点时若题库为空也会自动生成（点击即看到 15 题）；
- 题目材料 = 定义 + 来源句 + 笔记，避免只拿节点名出题。

验收：抽取后 6 秒，节点题库 15 题、status=ready。

### 副本真实挑战

流程：

1. 节点首次答对 1 简答 + 1 判断 → tier=1；
2. 流程链上所有步骤 tier≥1 → 副本 `playable`；
3. challenge 返回打乱步骤；提交正确顺序 → `cleared`。

领域：

1. 成员 ≥2 个 tier≥1 → `playable`；
2. challenge 生成 10 题混合题（填空/判断/解答）；
3. 填空/判断本地判（含包含/字符覆盖兜底），解答 LLM 判；
4. 10/10 → `cleared`。

实测：fixture 世界 8 个节点各答 1 简答+1 判断 → 两个副本都 `playable`；流程提交正确 → `cleared`；领域 10 题全对 → `cleared`。

修复：`submit` 现在只允许 `playable/cleared` 状态提交，防止未解锁直接通关。
