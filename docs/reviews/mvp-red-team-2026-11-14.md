## 1. 总体结论

1. **当前不满足两份文档对「MVP」的定义，只能称为「高保真交互原型 + 局部可演示链路」。** 按 MV 第 157—171 行的 A—E 阶段完成门槛，A 部分达成、B/C/D/E 均未达（详见 §2）；种子测试所需的邀请登录、账号隔离、备份恢复一条都不存在。
2. **最大风险不是功能缺失，而是「看起来已经完成」**：README 与界面把领域副本、隐藏、3D 标为已完成，但隐藏后节点仍在地图上、领域副本实际复用节点判断题、大量能力被 mock 顶替且不显示降级——评审者与用户都会被误导。
3. **VC 演示的最大风险是脚本第三段无法按文档成立**：当前示例世界 `0 attempts / 0 quizzes / 两个建筑均 locked`，且流程副本 steps 存的是节点名而非 id，按 MV 的解锁规则永远无法解锁「事先完成的旧流程副本」；同时 `server/.env` 没有配置 DeepSeek key，题库/判题当前只能是 mock 模板。
4. **做得最扎实的部分**：三档阈值与「不同题只算一次」的计数、无节点删除/正式关系不可删、隐藏的**服务端**连通性算法（临时图、无向 BFS、根节点保护、最近一次撤回）、示例数据标识、密钥只在服务端。
5. **建议的修复顺序**：先做两个「一行级」修复（隐藏真正不渲染、2D 为默认视图）与「演示真实性标记」，再做落图事务/幂等/排队，最后补鉴权与邀请码；否则越往后开发，越多投入会压在需要回退的范围上。

## 7. 最值得先修的前 5 项

排序依据：风险 × 修复成本 × 对演示/试用的直接价值。

1. **R-27 隐藏真正生效（成本 S，约 0.5 人日）**：`World.tsx` 过滤 `hidden` 节点与相关边，3D 同步过滤，徽标计数排除隐藏；补一条「隐藏后无孤岛」的验收用例。这是唯一被用户「已确认」却在界面失效的规则。
2. **R-33 2D 成为默认视图（成本 S，0.5 人日）**：`view3d` 默认 false，3D 降级为明确标注的实验开关（或移出入口）；同步修 README 与 ASSETS 说明。先让已投入的 2D 自定义节点/铁路/避障成为首屏，再谈视觉。
3. **R-52 去掉「假成功」（成本 S—M，1 人日）**：DeepSeek 失败不得静默回退 mock（或回退必须在 UI 明示「mock」并禁止标记为已保存）；豆包失败不得回放固定句落图；配置真实 `DEEPSEEK_API_KEY` 并把 provider 状态如实上报。
4. **R-03 落图完整性（成本 M，2—3 人日）**：一次抽取单事务提交；请求带 `sessionId/spanId/revision`，旧 revision 拒绝；每世界单任务+合并缓冲；对所有新实体强制建「探索来源」边；关系按 `(src,dst,kind)` 去重。这是发布门槛「同任务不重复落图」的前提。
5. **R-28 鉴权与邀请最小闭环（成本 M，2—3 人日）**：邀请码兑换→会话 Cookie（HttpOnly/Secure/SameSite）→每个世界 owner 校验→WS 握手校验会话+Origin；关闭/鉴权 `DELETE world` 与 `/api/dev/*`。没有它，10—20 人种子测试无法开始。

### 结论一句话

这版代码把「地图长得出来、能点开、能答题、能建副本」的可见链路做出来了，但把「隐藏、领域副本、3D、演示数据」四件事写成了已完成；在修掉 P0 的 8 项之前，它不能被称为文档定义的 MVP，也不适合直接给种子用户或 VC 演示。
