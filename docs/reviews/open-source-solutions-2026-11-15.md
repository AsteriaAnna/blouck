### 1.1 新增的关键参考（第一性原理检索）

1. **Knowledge Spaces**（MIT）— https://github.com/vanderbilt-data-science/knowledge-spaces
   - 从课程材料抽 knowledge items、建概念图/competences、用 QUERY 建先修关系、枚举 knowledge states、算 outer fringe、BLIM 自适应评估、生成学习材料；
   - 直接对应我们的"先修关系、边缘节点、副本可挑战、三档"；但它是文档/课程向，不解决实时语音与节点准入。
2. **Automated Concept Map Extraction from Text**（ACL 2025）— https://aclanthology.org/2025.ldk-1.10/
   - 神经符号 + GPT-3.5 的概念图抽取管线，代码开放；可作为节点/关系抽取对照基线；F1 25–28 说明任务本身很难。
3. **Reor**（AGPL-3.0）— https://github.com/reorproject/reor
   - 本地 AI 笔记，自动按向量相似连接相关笔记；说明"相似连接"不等于"语义关系"（我们关系必须分类/定向）。
4. **QuestFusion** — https://github.com/snehilaryan32/rpg-with-knowledge-graphs
   - KG + LLM 生成 RPG 任务；最接近"图谱生成副本"的开源尝试，但为研究原型。
5. **Interactive Fiction Worlds**（AIIDE）— https://ojs.aaai.org/index.php/AIIDE/article/download/7400/7309
   - PCG 世界/任务生成参考。
6. **BRING** — https://github.com/Eva-E1/BRING
   - LLM 角色扮演 + 多实体图记忆；NPC/世界/任务可参考。

## 2. 没有开源参考之一：节点准入

### 2.1 这到底是一个什么需求

**行为要求：**

1. 系统必须先判断"什么算节点"，再创建节点；
2. 节点是**用户的学习对象**：名词性概念，可解释、可出题、之后可能继续学习；
3. 必须先区分角色：
   - `topic` 话题主体 → 节点；
   - `subconcept` 理解主体所必需 → 节点（有定义/证据时）；
   - `process` 过程/工作流本身 → 节点（步骤进流程副本）；
   - `example` 举例 → 节点 MD；
   - `metaphor` 比喻/类比 → 节点 MD；
   - `step` 过程步骤 → 流程副本；
   - `noise` 口头语/玩笑/代词 → 丢弃；
4. 比喻/例子不能成为节点，也不能成为正式关系；
5. 过程句只建过程节点，步骤不建节点；
6. 误建后必须有纠错出口（改名/合并/隐藏/撤销/待确认）。

**验收场景（需求基线 V1/V2）：**

- "RAG 像灰姑娘一样都有悲惨的过去" → 只建 RAG；灰姑娘不进图；类比进 RAG MD；
- "工作流依次做输入解析、检索资料、生成草稿、审核发布" → 只建一个过程节点 + 流程副本，不建 4 个步骤节点。

### 2.2 可能会出现什么问题

| 问题 | 具体表现 | 后果 |
| --- | --- | --- |
| **喻体被当节点** | "RAG 像灰姑娘" → 建灰姑娘节点、RAG→灰姑娘关系 | 图被污染、关系不可信、还可能在灰姑娘上出题 |
| **一句话冒出很多节点** | 一个过程句生成 4–6 个"环节"节点 | 地图爆炸、节点无意义、后续关系混乱 |
| **步骤节点化** | 输入解析/检索资料/生成草稿各自成节点 | 与流程副本重复，流程排序出现两套对象 |
| **例子/类比当知识** | "比如 BM25" → BM25 作为正式关系 | 出题依据错误、用户误解 |
| **同义词拆点** | "重排/精排/重排序"三个节点 | 重复关系、副本成员重复、统计失真 |
| **否定/假设/引用被当事实** | "RAG 不是微调" → 建成 partOf | 关系方向/语义错误，出题错误 |
| **口误/ASR 术语错** | "Rerank" 被识别成 "Rerun" | 建错节点，且无改名出口 |
| **代词/模糊指代** | "这个东西很重要" → 建"这个东西"节点 | 无意义节点、无法出题 |
| **只提一次/无定义也建点** | 闲聊中的名词进入地图 | 节点无法解释、无法出题、用户不认 |
| **误建后无法纠正** | 没有改名/合并/隐藏/撤销 | 错误资产长期存在，参与关系/方向/副本 |
| **节点上限失控** | 每句话新增 5–10 个节点 | 实时生成体验崩坏，成本和延迟上升 |

### 2.3 为什么开源不覆盖

- DeepKE / GLiNER / GLiREL / 概念图抽取：只做 **mention/实体/关系识别**，不判断"学习对象/角色/教学价值"；
- Knowledge Spaces：假定 **knowledge items 已经给定**，它不负责从语音里判断什么算 item；
- Reor：用向量相似自动连笔记，**相似 ≠ 学习节点**；
- 通用 LLM 抽取：模型会"抽到名词就建"，没有角色/准入约束；
- 结论：**节点准入是教学语义层，必须自研规则 + LLM 判定 + 程序校验。**

### 2.4 验收要点

- 灰姑娘用例：0 个喻体节点、0 条比喻关系；
- 过程句：1 个过程节点 + N 步流程副本；
- 同义/否定/指代/口误用例：不建错误节点或可纠正；
- 每稳定片段新增节点上限；
- 所有节点有来源/证据，可解释。

## 3. 没有开源参考之二：关系方向

### 3.1 这到底是一个什么需求

**行为要求：**

1. 每条关系必须有明确谓词和**固定方向**：
   - `kindOf` 归类：具体 → 上位；
   - `partOf` 组成：部分 → 整体；
   - `prerequisite` 前置：前置 → 后续；
   - `contrast` 对比：无方向；
   - `alternative` 替代：旧 → 新；
   - `related` 相关：无方向；
2. 方向必须与证据一致，不能由模型/渲染随意决定；
3. 方向不确定时，不能建正式关系（降级建议/笔记/不建）；
4. 地图、关系卡、副本必须使用同一套方向语义；
5. 关系线视觉上要能表达方向（箭头/文案），不能只画一条线。

**验收场景（需求基线 V3/V7）：**

- "混合检索包含 BM25 和向量召回" → 必须落到 partOf（部分→整体）或 kindOf（具体→上位），方向正确；
- 关系卡能说明"为什么是组成/归类，而不是另一类"；
- 前置关系不能反（"先召回再精排"不能建成"精排→召回"）。

### 3.2 可能会出现什么问题

| 问题 | 具体表现 | 后果 |
| --- | --- | --- |
| **前置方向反了** | "召回后精排" 建成 Rerank→召回 | 流程副本排序答案错、用户学到反的 |
| **整体/部分反了** | "RAG 包含分块" 建成 RAG→分块（partOf 应为分块→RAG） | 组成关系无法解释、领域/流程判定错 |
| **kindOf/partOf 混淆** | "混合检索是一个检索方法" 建成 partOf | 归类错、领域副本把组件当领域 |
| **无方向关系画箭头** | contrast/related 也画单向箭头 | 用户误解为因果/依赖 |
| **方向线指向已建关系** | 已经建了 A→B，仍提示"下一步 B" | 重复/矛盾，探索体验差 |
| **环** | A 前置 B、B 前置 A | 流程拓扑无解，副本无法生成或硬判错 |
| **方向与隐藏/连通冲突** | 方向线被当作连通依据 | 隐藏后地图仍显示、孤岛判定错 |
| **多谓词同对冲突** | 同时有 A→B kindOf 与 B→A kindOf | 图自相矛盾，无法判断 |
| **方向依赖模型自由发挥** | 同一段文本两次抽取方向不同 | 结果不稳定，用户无法信任 |

### 3.3 为什么开源不覆盖

- DeepKE / GLiREL：关系分类输出 `head/label/tail/score`，**不定义方向约定**，也不校验方向与证据是否一致；
- ConceptNet / SKOS / schema.org：提供关系词表，**不负责从文本判定方向**；
- Knowledge Spaces：先修关系由 QUERY/专家给定，**不解决"从语音里判断方向"**；
- 概念图抽取：输出概念连接，**方向/谓词常常缺失或自由化**；
- 结论：**方向约定 + 证据校验 + 归一化是产品语义层，必须自研。**

### 3.4 验收要点

- 反向前置、整体/部分、kindOf/partOf、无方向关系、环、多谓词冲突六类用例；
- 关系卡必须展示"谓词 + 方向 + 依据 + 为什么不是另一类"；
- 地图箭头/方向线与数据方向一致；
- 方向不确定时不建正式关系。

## 4. 没有开源参考之三：谓词校验

### 4.1 这到底是一个什么需求

**行为要求：**

1. 关系必须归入六类谓词之一（或明确标为"非知识关系"）；
2. 证据必须能推出该谓词，不能只靠共现/相似；
3. 必须区分：
   - **知识关系**：kindOf / partOf / prerequisite / contrast / alternative / related；
   - **非知识关系**：analogy（类比）、example（举例）→ 只进 MD，不进图/题/副本；
4. 置信度与证据决定线型：正式 / 虚线建议 / 不建；
5. 同一对概念同谓词去重；同对多谓词/方向冲突必须有处理规则；
6. 关系名/说明必须可读、可解释，接受建议后生成正式名称/MD；
7. 用户可对错误关系提出争议/修订（正式关系不可删除）。

### 4.2 可能会出现什么问题

| 问题 | 具体表现 | 后果 |
| --- | --- | --- |
| **related 万能化** | 所有关系都标 related | 图失去语义，副本无法判断流程/领域 |
| **比喻被当 related** | "RAG 像灰姑娘" → related 正式关系 | 知识图被污染，出题/副本依据错 |
| **举例被当关系** | "比如 BM25" → RAG related BM25 | 例子变成知识，用户误解 |
| **contrast/alternative 混淆** | "A 替代 B" 与 "A 对比 B" 混用 | 替代关系错，学习路径/选择建议错 |
| **否定句当肯定** | "RAG 不是微调" → partOf | 事实错误，题目错误 |
| **证据只共现** | 两个词同句出现就建关系 | 关系噪声，图不可信 |
| **谓词与证据不匹配** | 证据是"先…再…"却标 kindOf | 分类错，关系卡无法解释 |
| **同对多谓词冲突** | kindOf 与 partOf 同时存在且方向矛盾 | 图自相矛盾，副本依据不清 |
| **正式/虚线门槛错** | 证据不足却建 formal | 用户看到错误实线，难以纠正 |
| **接受建议后无关系名** | 虚线接受后仍只有一句问句 | 关系不可读，无法出题 |
| **中文术语/口误** | "精排" vs "重排" 被当不同关系 | 同义关系重复，副本成员重复 |
| **模型不一致** | 同一文本两次谓词不同 | 结果不稳定，评测/信任崩坏 |

### 4.3 为什么开源不覆盖

- DeepKE / GLiREL：做**关系分类**，但不校验"证据是否推出该谓词"，也不区分**教学/比喻/举例**；
- GraphRAG/Graphiti：有 relationship description/strength，但没有我们的六类谓词与"非知识关系"约束；
- ConceptNet：提供词表与常识关系，不是"从用户话里校验谓词"的判定器；
- 概念图抽取：输出连接，但对谓词/方向/证据的约束很弱；
- 结论：**谓词体系、证据校验、非知识关系拦截、正式/虚线策略，都是产品自定义规则，必须自研。**

### 4.4 验收要点

- "包含/属于/先…再…/不是…/像…/比如…" 六类用例；
- 证据不足不得建正式关系；
- 比喻/举例不进入正式图、不出题、不作为副本依据；
- 同对同谓词去重、同对多谓词/方向冲突有处理；
- 接受建议后有可读关系名/MD。

## 6. 最终判断

### 可直接采用（组件级）

- **FunASR**：离线/自托管 ASR 备选；
- **GLiNER**：轻量实体候选（需中文实测）；
- **RAGAS**：评测框架组织方式；
- **3d-force-graph**：3D 渲染参考。

### 借架构/规则

- **Knowledge Spaces**：knowledge items、QUERY、knowledge states、outer fringe、BLIM；
- **Graphiti**：episode、实体归并、provenance；
- **ACL 2025 概念图管线**：概念/关系抽取对照；
- **Mem0/Cognee/LightRAG/GraphRAG**：增量/记忆/证据 prompt 参考；
- **Reor**：笔记自动关联的产品 UX（注意相似 ≠ 语义）；
- **QuestFusion/PCG**：副本/任务生成设计参考。

### 必须自研

1. **节点准入**（角色判定、比喻/例子/步骤/噪声拦截、纠错出口）；
2. **关系方向**（谓词方向约定、证据方向校验、归一化、箭头/关系卡）；
3. **谓词校验**（六类谓词、证据蕴含、非知识关系拦截、正式/虚线策略、争议修订）；
4. 实时语音→学习语义的端到端编排；
5. 副本出现时机/自由度/内容规则；
6. 图语义评测指标。
