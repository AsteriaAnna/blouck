# 生成算法

最后更新：2026-11-16

---

## 1. 目标

把一段学习输入变成：

- **名词概念节点**（不是关键词）；
- **归类/定位关系**（谓词 + 方向 + 证据 + 理由）；
- **边缘节点方向**（下一步学习路径）；
- **流程/领域副本**（由结构触发，不是随机弹窗）。

非目标：抽得越多越好；开放式知识库；关系题（MVP 延后）。

---

## 2. 主流水线

```text
ASR 稳定片段 / 文本（SourceSpan）
  → 概念候选（名称 + 类型 + 定义 + 别名 + 证据）
  → 规范化/去重（名称、别名、相似度）
  → 节点落图（位置 + MD 初稿）
  → 关系候选（共现 / 邻居 / 向量 top-k）
  → 关系分类（谓词 + 方向 + 证据 + 理由）
  → 方向生成（每个节点 0–3 条；仅 frontier 渲染）
  → 副本候选（流程链 / 归类簇）+ 硬校验
  → 评测与人工抽样
```

当前实现中，流式检测与最终落图还是两条链路，见 [current-state.md](../design/current-state.md)。

## 3. 节点

### 3.1 候选

输入：文本 + 当前焦点 + 已有节点。

输出：

```json
{
  "name": "Rerank",
  "type": "方法",
  "definition": "召回之后对候选集重新打分的精排阶段",
  "aliases": ["重排"],
  "evidence": "然后用 Rerank 精排",
  "confidence": 0.92
}
```

### 3.2 节点准入

| 规则 | 说明 |
| --- | --- |
| 名词性 | 节点名必须能回答"什么是 X？"；疑问句/命令句不是节点 |
| 长度 2–20 | 停用词/代词/动词拒绝 |
| 类型白名单 | 概念/方法/组件/指标/工具；"问题/领域/步骤"不是类型 |
| 证据 | evidence 必须是原文子串；没有证据不落图 |
| 置信度 | 低于阈值进"待确认" |
| 单片段上限 | 最多 5 个新节点 |

**步骤不是节点**：一个概念是不是步骤取决于上下文；流程候选只记录 ordered steps，不写回节点。

### 3.3 规范化

1. 名称/别名精确匹配 → 复用；
2. 向量相似度 ≥ 0.92 → LLM 裁决 `same / parent_child / different`；
3. 不明确时**不合并**（宁可多，不可错并）。

### 3.4 当前收敛：MD-first

后续讨论把"重类型/重本体"收敛为：

- 节点 = 学习锚点 + MD；
- `type` 可选、可后补，不作为准入门槛；
- 多数领域细节写节点 MD，不新增节点/边；
- 图只放导航所需关系。

详见 [problems-and-approaches.md](../design/problems-and-approaches.md) 第 1 节。

## 4. 关系

### 4.1 谓词与方向（固定）

| 谓词 | 语义 | 方向 | 线索 |
| --- | --- | --- | --- |
| `kindOf` | 归类 | 具体 → 上位 | 是一种/属于 |
| `partOf` | 组成 | 部分 → 整体 | 组成/包含/模块 |
| `prerequisite` | 前置 | 前置 → 后续 | 先/再/需要 |
| `contrast` | 对比 | 无方向 | 相比/区别 |
| `alternative` | 替代 | 旧 → 新 | 替代/换成 |
| `related` | 相关 | 无方向 | 明确关联但说不清 |

"包含"不单独存：落到 `partOf` 或 `kindOf`。

### 4.2 关系准入

- 有证据才正式；
- 低置信 → 建议（虚线）；
- 比喻/举例不进入正式图，写节点 MD；
- 正式关系不可删除；错误更正靠 revision/争议状态，不靠删边；
- 同一对概念最多 2 种谓词，且层级与 `related` 不同时存在。

### 4.3 关系 MD

每段关系有自己的 MD：谓词、方向、一句理由、来源证据、用户补充。

---

## 5. 方向

- 每个节点可以有 0–3 条方向（问题 + 理由 + 目标提示）；
- 只有 **frontier** 节点把方向画成线；
- frontier = 正式关系出度为 0，或新节点尚未展开；
- 点击方向 → AI 对话 → 产生新节点/关系 → 该方向 `consumed`，重新计算 frontier；
- 非 frontier 方向放节点 MD 的"继续探索"。

---

## 6. 副本

### 6.1 流程副本

- 候选：同一过程/体系；
- 硬校验：3–6 步、相邻步骤有过程证据、顺序唯一、每步有来源；
- 状态：detected → playable → cleared；依据失效 → stale；
- 玩法：步骤连线排序；
- 通关后保留，可回看，有可编辑 MD。

### 6.2 领域副本

- 候选：≥4 个概念属于同一领域；
- 硬校验：共同上位概念或共同来源；不能只靠共同邻居/"属于"边；
- 状态同上；
- 玩法：每天 10 道混合题（填空/判断/解答）。

### 6.3 出现 ≠ 可挑战

- detected：地图上出现建筑，但未达挑战条件；
- playable：可进入；
- 直接挑战 detected 副本应返回 409。

## 7. 评测基线

脚本：

- `server/eval/run.ts`：抽取/关系 12 个案例；
- `server/eval/dungeons.ts`：副本 15 个正负例。

最近基线：

| 指标 | 值 |
| --- | --- |
| 关系 Precision | 32.4% |
| 关系 Recall | 46.0% |
| 谓词准确率 | 87.0% |
| mapType 准确率 | 91.3% |
| 证据覆盖 | 46.0% |
| 副本 TP/FP/FN/TN | 2/0/0/13 |

结论：关系召回和证据覆盖仍是主要短板；副本校验规则目前是可靠的。

---

## 8. 已知算法缺口

1. 节点准入没有稳定的角色分类（比喻/例子/步骤仍可能误建）；
2. 谓词选择不稳：`partOf` 万能化，`kindOf` 漏；
3. 关系证据覆盖低；
4. 流式检测与最终抽取是两套结果，缺少 reconciliation；
5. 没有 provisional 实体与 revision 的完整闭环。

详见 [problems-and-approaches.md](../design/problems-and-approaches.md)。
